🎯 概述

上节课我们见识到了 || (OR) 短路赋予了我们多爽的默认备胎填充能力。但那是一个沾有巨毒苹果糖！在真实的软件系统中，当你的应用合法地吐出数字 0 甚至是空白字符串 '' 时，一概把它们当 Falsy 轰炸的 || 将产生灾难级踩坑。于是，新版 JavaScript 派出拥有着冗长滑稽名字的猛将 —— Nullish Coalescing Operator（空值合并运算符 `??`） 来拯救世界。

1. OR 短路的致命隐患：数字 0 被无辜“误杀”

上一次，我们的问题悬念结冰于这行代码片段：客座预定人数刚好当天是冷清的 0 人。

const restaurant = {
    numGuests: 0
};

// 我们本意想要捕获出真实当晚的数字 0
// 但 0 触发了 falsy 原罪，被直接判定为不存在，误被顶成了兜底的大额假数字 10！
const guestsFallbackError = restaurant.numGuests || 10;
console.log(guestsFallbackError); // 10 💣

底层逻辑哲学探究 - 为什么会这样？
?? 就像是一个瞎子版、极其宽容且豁达的老好人 ||。
在之前的 OR 眼里，它的击杀追捕名单叫：Falsy。它痛恨包含（undefined, null, 0, '', NaN）内的所有元素。

而在 ?? 眼里，它的击杀追捕名单更换成了一份严苛的小册子：Nullish 值。这个崭新的阵营里面仅仅孤单地躺着两位老大哥 —— 只有极其严重的空洞本体 null 和 undefined 才算是空值。至于数字 0 和空字符串 ''，被当成了正常的平民 Truthy，受到保护而被拦截短路。

❓ 理解检测

1. 彻底辨析：在 `??` 这个运算符的内部逻辑世界里，下列哪些元素会像引发短路跳开的墙壁防线（即具有类同 Truthy 的防御权）？
A) 只有像 true, 23, "Jonas" 这些实实在在包含大实体的丰满结构。
B) 除了 null 和 undefined 会导致它直接穿过并取默认值，其它你丢的诸如 数字 0 甚至是 空串（""） 都一律被视作坚固存在并受保护返回！
C) 它防范所有错误，NaN 和 null 等都会被当作是 Falsy，返回后面的后备数据。
B 是正确的选项。这也是 ES2020 增加它以弥补早期 || 的过于一刀切霸道带来的填坑操作。在未来应对数据 API 表单时，你会天天使用它的！
