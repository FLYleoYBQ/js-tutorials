Optional Chaining (?.)

📺 来源：014 Optional Chaining.en.srt 📂 章节：第 09 章
📌 知识脉络
  • 前置基础：从外部 Web API 拉取充满不确定性的深深嵌套且部分内容残缺缺失的 JSON 数据流。
  • ES2020 究级武器：配合我们学果的那位叫 ?? 的英雄，我们彻底告别了一层一层的冗爆了的无聊防爆 If 检查语句。

🎯 概述

你有没有尝过被满屏惨烈的控制台红字 TypeError: Cannot read properties of undefined 支配的恐惧？当我们在一个巨大的未知嵌套数据里向深处试探获取变量时，如果这条途径中间断开了（遇到了不存在或者空包），继续往深处挖掘，就会遭受 JS 毫不留情的红屏击鼓。现在，可选链 (Optional Chaining `?.`) 像铺上了软垫一样帮你安静化解这场致命碰撞。

1. 逃离 undefined.xxx 引起的地狱崩溃

当我们要获知在礼拜一这一天，餐厅到底是几点关门的时候，麻烦悄然逼近：餐厅根本没写星期一（mon）营业这个属性！

💣 常规硬闯引发车祸
const restaurant = {
    openingHours: {
        fri: { open: 11, close: 23 }
    }
};

// 'mon' 是不存在（undefined）的。
// 所以你等同于在执行 undefined.open
// 这直接导致引擎立刻红字报错崩溃！
console.log(restaurant.openingHours.mon.open);
🛡️ 史前人类的老实搭桥护栏法
// 以前想安全爬出大坑，我们不得不一步一回头铺满啰嗦的 if 护栏探测垫脚石：
if (restaurant.openingHours && restaurant.openingHours.mon) {
    console.log(restaurant.openingHours.mon.open);
}

👑 现世代魔法：可选链 ?. 侦查防撞机制：

只要在 . 之前塞入 ?，就如同在探照灯上加上安全护罩：只要问号前面的东西不存在或者是一个坑（nullish概念：null / undefined），那么引擎立马收起探测针，和平归还一个 undefined 停手退步！绝不动手导致崩溃报错。

// 问号放置在要踏下去的前进跳板前：
// 翻译：只有当 mon 本身真的客观存在 (不空塌)，我才敢往下走去读 open
console.log(restaurant.openingHours.mon?.open); // 返回: undefined

// 多重安全防爆叠加探测（极度深层结构）：
console.log(restaurant.openingHours?.mon?.open); // 安全返回: undefined

2. 最强羁绊：与 ?? 空值合并结为伴侣使用

既然 ?. 会在遇到深坑撞车时，聪明地软着陆并返回给你一个不报错的 undefined，那么谁是拦截兜底 undefined 给它设置默认替补变量的之王呢？当然是和它一母同胞的亲兄弟 ?? 咯！

3. 兼容性延伸：不仅能防参数塌楼，更能探路方法和数组！

在企业深层应用里，它不仅仅可以用在读取不知猴年马月是否存在下落的对象属性。如果你甚至不知道它身上挂没挂上这个执行函数！或者该数组有没越界为空值！同样一把通吃照样可以用 ?.：

// 🕵️‍♂️ 探测内部深层函数执行存活状况：
// 翻译：只有 order 这把武器确实攥在手里存在且是个实体函数，那才打响后面它()内部的弹药！否则直接短路默认不存在！ 
console.log(restaurant.order?.(0, 1) ?? 'Method does not exist'); 
console.log(restaurant.orderRisotto?.(0, 1) ?? 'Method does not exist'); // 方法未登记，拦截生效


// 🕵️‍♂️ 探测数组首坑位存活状况防空军：
const users = [{ name: 'Jonas', email: 'hello@jonas.io' }];
// 翻译：只有这头数组队列里它的零号铁王座上面有人坐，才读他的名字。
console.log(users[0]?.name ?? 'User array empty'); // 'Jonas'

const emptyUsers = [];
console.log(emptyUsers[0]?.name ?? 'User array empty'); // 'User array empty'

❓ 理解检测

1. 为什么我们认为 `?.` 和 `??` 在新法典里是配合起来天衣无缝的双生伴侣？
A) 它们其实是对立竞争关系的，两者在性能优化上打成平手。
B) 因为 `?.` （可选链防撞墙）在侦查前方道路遇到塌陷空洞时，它拦截后静默抛出/退回的一定且永远是一个名为 Nullish (undefined) 的信号火炬。而恰巧 `??`（空值合并兜底）的作用靶心触发名单里仅关注拦截并转化这种特殊的核心火炬信号。
C) 因为它们都是包含 "?" 符号组成家族。属于格式上的美学追求而已。
B 是正确的选项。这是 ES2020 顶层建筑大师级组合操作：前锋用 ?. 以 Nullish 原理进行前路探查排雷，后防用 ?? 靠 Nullish 原理接收抛出失败弹道并安上防滑锁。组合起来所向无敌。
