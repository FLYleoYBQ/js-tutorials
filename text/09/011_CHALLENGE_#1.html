📝 需求描述

我们正在打造一家体育竞猜网站，下面是一个你从接口网络拉取下来的深层嵌套的足球数据对局比赛图谱对象 game。你需要：

  1. 抽取分离两支对战球队的首发名单各建成独立的数组 players1 和 players2。
  2. 通常球队排位里的第一个名额留给守网长，请专门针对 Team 1 也就是伟大的拜仁大军将它的首发抽出一个独立将领变数被封为 gk，且其他参战战士收集进名为被称做 fieldPlayers 的集体队列里。
  3. 建立一个总兵团：制作个被名为 allPlayers 新巨型数组将两方兵力混编揉杂合并到一块。
  4. 第一梯队决定进行战术换血使用三名生力军后补力量下半场强攻：利用其初始团队结合三人组（'Thiago', 'Coutinho', 'Perisic'）生成一个名叫 players1Final 的重组后队列。
  5. 我们需要提取竞猜赔率表里包含的核心属性字段以便分析风向。根据 game.odds 中的 3 枚关键值生成等名被命名叫起外号叫做 team1, draw(替代原本平局小鬼子 x 变量命名丑态), team2 的散落零件提取变数出来。
  6. 提供了一份超凡记录：搭建名叫 printGoals 的灵活核算战力通报函数机器：允许接收无论是随机投进来的孤勇者们还是结对名单。每投一点就播报一个士兵其伟业大名然后宣布本战合算了多少次斩杀球个数！
    测试通过如下的投喂：首先塞这四个名单人 ['Davies', 'Muller', 'Lewandowski', 'Kimmich'] 看看是否打平预估，再接着测试一次拿已经储存在了原始母盘里面打好的入球猎手 game.scored 中的成员强塞进去玩玩看。
  7. 最终智能猜胜负引擎。严禁运用如果（If...Else...）及那套古板带有问号的三元魔法式子判断阵法，采用硬操作逻辑，推算出哪方的胜出希望最大（规则：赔率反倒偏小的那方为最安全保险）且直抛大广播播回显终端屏幕。

// 1. 利用最基础平铺分解剥开分队：
const [players1, players2] = game.players;

// 2. 利用数组左边...打包剩余归属：
const [gk, ...fieldPlayers] = players1;

// 3. 右手大展宏图将包裹暴力泼洒汇聚（Merge合流）：
const allPlayers = [...players1, ...players2];

// 4. 重复上门道倒接添加散工组人：
const players1Final = [...players1, 'Thiago', 'Coutinho', 'Perisic'];

// 5. 将属性提取甚至内部改名大魔法：
// 相当于跳出嵌套，拿了team1, 将 x 的身价赋予给全新名叫 draw 的名下保存！
const { odds: { team1, x: draw, team2 } } = game;
console.log(team1, draw, team2); 

// 6. 用上 Rest（函数形参...装水）和 Spread(呼唤调用前喷水解构)
// 原旨：将打通投下的一百发实心弹珠尽情聚集成名叫玩家兵线的弹药库去遍历和称量！
const printGoals = function (...players) {
  console.log(`一共有 ${players.length} 次破阵球！`);
};
// 测试 A：随机呼吁。
printGoals('Davies', 'Muller', 'Lewandowski', 'Kimmich'); 
// 测试 B：硬灌数组。直接用 ... 发撒

// 7. 奇招巧思！巧妙逼死三元公式结构，通过 && 拦截！如果赔率小就代表大火。
// （这里由于要判断并执行，&& 代表如果前置位达成满足真实通关状态才会让出继续触发下半阕输出播报句子！）
team1 < team2 && console.log('Team 1 is more likely to win');
