Rest Pattern and Parameters

📺 来源：007 Rest Pattern and Parameters.en.srt 📂 章节：第 09 章
📌 知识脉络
  • 前置知识：展开运算符 (Spread Operator)、数组和对象的解构赋值
  • 核心突破：理解剩余模式的“压缩打包”特性与展开运算符的“解压缩拆解”特性互为镜像。

🎯 概述

上节课我们学习了展开运算符 (...)，它可以像气球爆裂一样把数组里的元素全“喷洒”出去（解压缩）。今天我们来见识一下它的孪生兄弟：剩余模式 (Rest Pattern) 及其引申的 剩余参数 (Rest Parameters)。它们长得一模一样，都是三个点 (...)，但做的事情却完全相反——它是用来把零散的元素像吸尘器一样收集打包成一个数组。

1. 在解构赋值中使用剩余模式

它是叫“展开”还是“剩余”，完全取决于这三个点写在哪边：在 = 右边就是展开，在 = 左边就是剩余模式。

🚨 痛点复现： 当你在解构前几个关键元素后，想把后面数不清的剩余元素统统放进一个“备用盆子”里时，如果徒手去切数组会很难看。这时候剩余模式登场了：

⚠️ 必须遵守的核心军规：
由于引擎需要知道把哪部分算作“剩余”，所以 ...rest 必须永远放置在解构分配的最末尾，并且一次分配中只能拥有有且仅有一个剩余元素收集器。它甚至不会包容被中间 , , 剔除跳过的隐形元素。

2. 在函数传参中使用剩余参数 (Rest Parameters)

想象我们正在开发一个高级计算器，或者一个餐厅的随意点配菜系统。我们希望传入 1 个参数可以运行，传入 100 个参数也能运行！过去你会遇到参数越界丢失的问题，现在 剩余参数 可以把形参接收站变成黑洞：

💣 常规硬编码传参
const add = function(a, b, c) {
    return a + b + c; // 如果你要传入 4个数字怎么办？
};

add(2, 3, 5); // 正常返回 10
add(2, 3, 5, 7, 1); // 超出的 7 和 1 会被可怜地丢弃过滤！
🛡️ 剩余参数进化版
// 无论外界砸来多少颗子弹，都会被没收进 numbers 数组！
const add = function(...numbers) {
    let sum = 0;
    for (let i = 0; i < numbers.length; i++) {
        sum += numbers[i];
    }
    console.log(`我强力吞噬了这批巨量参数得到了: ${sum}`);
};

add(2, 3);
add(5, 3, 7, 2, 99, 13); // 无限火力全收！

// 终极连招：将已有数据池倒水进去再被收集
const x = [23, 5, 7];
add(...x); // 前面的 ... 是 Spread（倒水），接收参数处是 Rest（装新盆）

❓ 理解检测

1. 在什么情况下 `...` 代表 “剩余模式(Rest)”，什么情况下代表 “展开操作符(Spread)”？
A) 在等号 (=) 左边接收解构变量或作为函数形参定义时，它是“剩余打包器”；在等号右边或主动呼叫函数填充实参传值处，它是“展开喷洒器”。
B) 在等号右边时就是 “剩余打包器”，等号左边是 “展开喷洒器”。
C) 取决于其后方跟着的数据是数组还是对象。对象固定为剩余模式。
A 是正确的选项。Spread 用在预期多个散落 值 (values) 逗号分隔的地方；而 Rest Pattern 用在预期需要声明多个散落 变量名称 (variable names) 去承接数据的地方。
