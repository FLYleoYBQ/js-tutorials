🎯 概述

短路判定在设置默认值时非常有效。不过，每次我们要把查验出的默认值，重新回写给原来的那个属性变量时，代码看起来总是异常的臃肿，例如：rest1.num = rest1.num || 10。左右两边存在肉眼可见的冗长复制！
2021 版的 JavaScript 为这种现象直接发放了逻辑赋值运算符组合套装 (||=, ??=, &&=)，进一步缩进前瞻框架代码体量。

2. 填平空值坑：空值分配 (??=)

这又是一脉传承在上一节的死穴：如果你其中一家连锁门店确实惨淡营业，当晚 numGuest 直接记录为凄惨的 0 呢？||= 就会犯花痴导致依然把它修改成强制硬塞的 10。

于是我们直接替换使用逻辑 nullish 赋值符：

const rest3 = { name: 'Empty Bar', numGuests: 0 }; // 0 是合法的

// 只要不是空无所有的 undefined 和 null，请通通放宽网面拦截下来，不要强塞 10。
rest3.numGuests ??= 10;

console.log(rest3.numGuests); // 完美停住并持有真实的 0！

3. 过滤涂改：逻辑 AND 赋值 (&&=)

还记得 && 象征着什么吗？只吃香甜甘果（即遇到 假值 Falsy 即短路阻断）。
假设你的合规风控需求：只要某家餐馆里目前确实含有明面上的大老板登记人（存在 owner 且为 truthy），我们为了防止数据隐私泄露，就拿块修正液全部涂抹成 'ANONYMOUS'。

💣 常规覆盖与错误下水隐患
// 假若老套写...你会发现把并没有拥有者的餐馆强塞了未定义标签！
rest1.owner = rest1.owner && 'ANONYMOUS';
// rest1（明明没有老板）这下平白无故沾染出了一个 
// owner: undefined 这种畸形的无赖占位属性空壳子。
🛡️ ES2021 完美刺杀替换
// 语义直译：如果并且只有当这个变量目前真的是一片大好 Truthy 的存在状态。那就狠狠赋值给覆盖改掉它。
rest1.owner &&= 'ANONYMOUS';
rest2.owner &&= 'ANONYMOUS';

// 终局揭晓：
// rest1 完全毫发无损，甚至根本没被硬塞一个 undefined 的壳。
// rest2 老板名字消失被覆盖成了 ANONYMOUS。

🧪 学习验证

❓ 理解检测

1. 我们为什么在特定隐私涂改操作中极度赞美 `&&=` 算子，而不是直接使用老式的 `obj.prop = obj.prop && '新值'`？
A) 因为如果该属性原本压根不存在，老式写法会强行给你把这个不存在的阴魂属性印进对象树内（生成属性名为 undefined 的废壳结构），而全新时代的 `&&=` 会极其克制，如果发现前头就是个伪假物直接静默不干活不动刀。
B) 因为它跑起来运行内存占用大幅下降。
C) 对于 && 判断，老式和新式没有任何结果区别，仅仅就是语法糖的少打字炫技。
A 是正确的选项。它不仅仅省力。更是彻底剪除了以往必须用 If 包裹防爆兜底代码块和被强赋值 Undefined 洗版的垃圾残留脏数据隐患问题。
