2. for-of：Map 骨子里的无缝穿梭融合

上一次针对大笨重对象进行 for-of 循环的时侯，对象像只不吃草的牛，我们求爷爷告奶奶硬砸上 Object.entries() 去把它击成碎片数组才硬喂进去。

而 Map 天生骨血就是一头纯正的 Iterable (可迭代生灵)！它自身长满了可以攀岩吸附的孔洞，直接丢进 for-of，配合极速手术刀 [key, value] 破坏力惊人拉满解爆：

console.log(question.get('question'));

// 天生可以完美对接 for-of 接口！解构小分队冲进去拿人：
for (const [key, value] of question) {
  // 只捞出指纹扣是正统“数字”类型的题目选项来展柜示众！
  if (typeof key === 'number') {
    console.log(`选项解答号牌 ${key}: ${value}`);
  }
}

// 假装用户瞎猜了答案 3 （你可以用 prompt('你猜？') 在浏览器拉出窗口测试）
const answer = 3;

// 直接把布尔裁决当钥匙抛给锁口！提取神圣回应。
console.log(question.get(answer === question.get('correct')));

3. 逆向拆骨：散架重组回阵列 (Array)

当你拥有了一个精巧的 Map 体系，想把它的血液抽离换回成那副最基础傻瓜易用的工业化阵列数组以用其他杀器。只要掏出 Spread (...) 散弹枪，轰击它重新罩进 [] 骨灰盒中：

// 直接全部融毁分解抛回成 Array
console.log([...question]);

// 甚至在 Map 独有长在自身的特供过滤口器里面打碎单抓：
console.log([...question.keys()]); // 只要左边那些全套锁扣
console.log([...question.values()]); // 只要右边那些全是肉质体

❓ 理解检测

1. 将原始的 Object（对象）投下并融化进入 for-of 循环池和把新世界的 Map 投进 for-of 循环池中，它们各自的操作工序有什么根本体征上的摩擦？
A) 没分别，它俩都不具备内置步进马达，都必须呼叫顶级法师 Object 给敲碎并进行包办。
B) Map 出生底座就打磨切口抛光兼容挂接了 Iterable (自带可直接走入遍历齿轮的引信)，像进进出出吃面条一样轻松，能够不用套取辅助壳就能被 for(... of MyMap) 直接吸入切片。而 Object 没有引信只能借助外力 Object.entries(OBJ) 碎块化包装借位引渡。
C) Map 根本就进不去 for-of 的管子内部，完全报红色错。
B 是正确的选项。Map 是在现代框架和后端数据拼装领域非常强势的数据池，它解决了传统对象的弱弱不规范杂乱感。天生的 Iterable 血统使其可以完美的随时随地进入任何阵列组合车间被重塑翻滚。
