Looping Objects: Keys, Values, and Entries

📺 来源：015 Looping Objects Object Keys, Values, and Entries.en.srt 📂 章节：第 09 章
📌 知识脉络
  • 前置基础：我们可以用 for-of 去遍历拥有 Iterable (可迭代) 法则的数组兵团。
  • 打破屏障：对象本质是一块被钉住静止的 非可迭代块 (not Iterable) 木头。但这节课，教你运用三种原生转换咒印，将其粉碎融化为 for-of 极易下口的数组。

🎯 概述：曲折迂回的“间接”刺杀

普通的铁憨憨没法直接用 for-of 去强行巡视一头字典般庞大的大象（对象对象本身）。我们得先依靠 JavaScript 本体内核对象神明 (Object 顶级构造器本身) 这颗水晶脑，朝它扔进去这头巨象请求粉碎置换，榨成能让 for-of 吸水的汁液数组 (Array) 然后间接去喝掉它。

2. 只索取右半边实体内脏肉：Object.values

如果业务流根本不想看它是哪天上吊干活，只想知道它们几点作息工作（只取右半值），那就使用 Values 提取右阀：

const values = Object.values(openingHours);
console.log(values); 
// 结果全部是对象内部藏着的肉：[ { open: 12, close: 22 }, { open: 11, close: 23 }, { open: 0, close: 24 } ]

3. 双手全抓的粉碎式全拿去法阵：Object.entries

既然你想完完全全将对象的壳子彻底模拟转化循环打印到终端屏幕（包括钥匙键和保险箱底下的内容值体统统全部囊括其中）。那就动用核武器 Object.entries()！此招会直接将整个对象融化分解切片成一连串首尾相接的 “装有键+值对的 数组包数组的包子铺”。

const entries = Object.entries(openingHours);
// 打印看看这壮观的二次元切片数组矩阵阵列：
console.log(entries);
// [ 
//   [ 'thu', { open: 12, close: 22 } ],
//   [ 'fri', { open: 11, close: 23 } ],
//   [ 'sat', { open: 0, close: 24 } ]
// ]

// 配合 for-of 以及 嵌套二阶级解构大法 (Destructuring)，极致华丽打印！
// 重点：[key, value] 中的 value 在此处本身就依然是一个 { open, close } 结构的内脏所以能够二次解包剥离！
for (const [day, { open, close }] of entries) {
    console.log(`星期 ${day} 这天，我们将在早晨 ${open} 点开门，战斗到夜晚 ${close} 点关门。`);
}

❓ 理解检测

1. 为什么我们在抽取对象身上的条目时要被迫使用 `Object.entries(myObj)` ，而不能像数组那样轻松写意地挂个尾巴写 `myArr.entries()`？
A) 因为对象在底层构造和基因血统里是不具备 Iterable（可迭代环绕天生步进光环的）。它自己没生出这种自转本事挂在底座上。所有强制提取循环都得靠着叫长辈大佬（顶级全图鉴构造器 `Object` 主力身躯）将它扔进熔炉中打碎铸造成临时数组代为行使循环。
B) 因为 Object 比较少见没人用。所以引擎开发程序员懒得做兼容了。
C) 两者没有丝毫区别。我就是瞎写成什么样都一样能跑出同样的结果，爱啥啥。
A 是正确的选项。这是原生根基上的界限设定，对象（字典）为了随机读写飞快，它没有给自个排序加上首尾排队的铁链。通过 Object 的全局借力能完美的在它俩基因隔阂上建接通桥。
