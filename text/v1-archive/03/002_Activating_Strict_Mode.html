🎯 概述

在继续深入学习 JavaScript 之前，我们必须先激活一个特殊模式——严格模式（Strict Mode）。严格模式能让我们写出更安全、漏洞更少的代码。这节课将向你揭示严格模式如何阻断无声故障，以及如何规范我们的变量命名。

1. 什么是严格模式？

严格模式是 JavaScript 中的一种限制性运行状态。要唤醒它，只需在脚本的最顶部输入一个简短的特殊字符串指令：

strict-demo.js

严格模式帮助我们避开隐蔽的 Bug（Bug 是指代码中的错误）。主要通过两大机制：

  • 🚫 禁止某些不良操作：不允许执行某些容易出隐患的操作。
  • 🚨 将“无声失败”变为可见错误：在普通模式下，部分写法错误，引擎只会默默失败；而在严格模式下，它会抛出明确的控制台错误。

3. 面向未来的保留字

严格模式还会帮语言的未来“占座”。它会预先封锁一些特定的名字，不让你用来做变量名。比如 interface、private 等等。

index.js

如果你使用了这些词汇，在严格模式的约束下，会报 Unexpected strict mode reserved word 错误。这是为了防止未来 JavaScript 引入这些关键字时引发系统冲突。

🧪 学习验证

❓ 理解检测

1. 要想让整个脚本都生效严格模式，`'use strict';` 应该放在哪里？
A) 放在最后一行
B) 任何地方都可以，只要带有单引号
C) 必须放在脚本最开头的代码行（注释语句除外）
解析： C 是正确的。解析引擎要求严格模式的声明必须是脚本中的第一条语句，否则它将不被识别为对整个作用域开启严格模式。
2. 严格模式对付 "拼写错误的变量" 时，有什么直接表现？
A) 自动纠正拼写
B) 抛出 ReferenceError 未定义错误，阻止静默失败
C) 无休止的弹窗警告
解析： B 是正确的。普通模式下它会在全局悄悄生成一个新变量（静默失败），而严格模式会直接拦截并抛出 ReferenceError，帮你揪出 Bug。
