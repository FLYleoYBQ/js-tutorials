🎯 概述

你知道吗？在 JavaScript 宇宙里写函数不止一种方法。今天向你隆重介绍“函数界”的两条巨龙：函数声明（Function Declarations） 与 函数表达式（Function Expressions）。它们长得很像，但在底层的时序运行上有关键差异。

1. 函数声明与表达式双雄对决

上节课我们用来创建函数的语法，就叫做“函数声明”。但我们也可以像声明一个变量一样把函数附在变量里，这叫“函数表达式”。这引出了 JavaScript 中极其重要的一个硬核事实：函数在 JS 里实际上也是一个值（Value）！，既然是值，我们理所当然能把它存进 const 变量中。

2. 隐秘差异：Hoisting 解析提升

那么它们到底有什么区别呢？最大的实操差异在于能否在定义它们之前提前调用。

🧠 底层原理（Behind the Scenes）：
这归功于 JavaScript 内部一种机制：作用域提升（Hoisting）。对于声明式，JS引擎会在代码正式执行前将其隐形置顶；但对于存放在变量里的表达式函数，依然受 const / let 到达定义前不可用的限制。

💡 Jonas 建议：该用哪个？
这大多取决于个人偏好。Jonas 本人更喜欢函数表达式，这能强制养成良好的代码组织结构习惯——必须先把函数踏踏实实地在顶部定义好，然后才去调用它；此外它能时刻提醒你，函数也是一种变幻莫测的“值”。

🧪 学习验证

❓ 理解检测

1. 关于“函数在 JavaScript 中只是一个值”这句话，以下哪个说法是佐证？
A) 可以在字符串中嵌入函数
B) 函数可以像数字、字符串一样被赋值给一个变量并存储
C) 函数可以和数字进行数学运算
解析： B 是正确的。因为它是属于系统中的值，可以绑定给一个常量（如 `const calcAge2 = function(){}`），这一事实正是函数表达式能够成立的基石。
2. 为什么函数表达式往往无法在定义代码之前被调用而报错？
A) 因为它被赋值给了 const / let 声明的变量，在初始化之前无法读取。
B) 因为它缺少了函数名字。
C) 因为函数表达式在系统内执行较慢。
解析： A 是正确的。即使是函数，一旦它作为值装进了由 `const` 定义的变量匣子里，就会遵循 `const` 的规则，不可在初始定义它之前使用它。
