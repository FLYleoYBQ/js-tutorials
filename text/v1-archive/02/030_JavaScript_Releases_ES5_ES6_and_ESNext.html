JavaScript 演化历史：ES5, ES6+ 和 ESNext

📺 来源：030 JavaScript Releases ES5, ES6+ and ESNext.en.srt 📂 章节：第 02 章 (终章)

这是基础部分的最后一块拼图。在使用最新的 JS 语法纵深挺进前，我们需要了解一件事：为什么网上有些代码用的都是极其落后的古早风格，而且大家都在讲 ES6、Babel 和 Transpiling？

1. “绝不打破互联网”之铁律 (Don't Break the Web)

⚠️ 后向兼容 (Backwards Compatible)

由于 JavaScript 最初（1995年）由 Brendan Eich 在仅仅的 10 天内设计出来，里面充满了一些离谱的缺陷。但是！为了防止升级语言导致世界上90年代建立的千万个老网站一夜崩溃，ECMAScript 委员会定下最严格的铁律：几乎永不废弃旧的写法。

哪怕是写于 1997 年的代码放到现今（2025年+）的最新浏览器里，它也一定会完美运行。因此 JS 更新只增加新功能缝缝补补，而不做切割和替代。这也是它有着“大杂烩感”历史包袱的原因。

2. 现代术语：ES5、ES6+、ESNext

  • ES5：属于古董基准。发布于大约 2009-2011 年间。它可以兼容一切浏览器，甚至是 IE9。我们往往把 JS 代码转译成 ES5 的形状，以让世界上网最龟速的老爷爷的手机也能无障碍浏览我们的商业网站。
  • ES6 (又称 ES2015)：改变世界的那一年，发布了超级大量的新特性（let/const, 箭头函数, Classes 等）。由于后续每年都会挤牙膏更新，我们现在将 ES6 以及后续所有的发布统一称为 ES6+ (Modern JavaScript)。
  • ESNext：代表在实验室中“尚未定版出炉”，但部分现代神仙浏览器已经实装的高危尝鲜特性。

3. 转译与向后支持 (Transpiling / Polyfilling)

你写着最时髦现代的 ES6+ 代码，但一旦上线 (Production Stage)，你无权决定用户的浏览器是否更新到了最新。因此，整个 Web 端行业发展出了一条管线工具（例如 Babel）。我们在部署应用前，往往会让工具将未来风的新酷语法强行降级“降维翻译 (Transpile)”成冗长但毫无兼容问题的 ES5 代码。

这解释了为什么在本课程后续教学中，我们依然会揭秘那些属于古老岁月、非常拗口的语法设计方案——因为当你进入企业级仓库，那些庞大的屎山旧代码必定都是用最底层陈旧的思维逻辑编写的！
