let, const 和 var 声明与常量

📺 来源：008 let, const and var.en.srt 📂 章节：第 02 章

一直以来我们都在用 let 来声明变量。但其实在现代 JavaScript（ES6及之后）中，创建变量的主力有两员大将：let 和 const。而 var 则是一个已被淘汰的老古董。

1. 变量变异者：let (可突变)

我们使用 let 来声明那些在程序运行的过程中注定会被改变（重新赋值）的变量。比如一个人的年龄会随着时间增长。

在专业术语中，重新赋值被称作突变 (Mutate) 一个变量。

let age = 30;
age = 31; // 完美突变，30 岁变成了 31 岁
let currentYear; // let 允许你先造一个空箱子 (undefined) 等待后续发落
currentYear = 2024;

2. 绝对不可动摇者：const (不可突变常量)

const 意为 Constant (常量)。使用 const 声明的变量，它的值被焊死了，在未来的任何时候都绝对不允许被修改和突变。

因为它的值必须是铁打的，所以你不能创造一个空的 const 变量。

🏆 最佳实践哲学

💡 黄金法则：默认始终使用 const！

作为编写整洁、安全代码的最佳实践：只有当你100%确信这个变量在未来必须发生变化时（比如循环计数器），才使用 let。

为什么？因为允许变量随意突变 (Mutate) 是程序引发 Bug 的万恶之源。尽可能把不需要变化的量封死成 const，能帮助你避免大量低级错误。

3. 历史幽魂与无耻裸写：var 与隐式污染

关于 var (已被时代淘汰)：
var 是 ES5 时代（2015年以前）声明变量老方法。表面上它能像 let 一样随意改变值。但实际上引擎底层的挂载方式（函数作用域 vs 块级作用域）截然不同。对于你而言，在平时编码时应当把它视作毒药，绝对不要使用，只要知道它的存在是为了看懂史前老代码即可。

关于裸写赋值 (未声明污染)：
初学者可能会发现，即使不用 let/const/var，直接写 lastName = "Schmedtmann"; 程序也能跑！

🚨 警告：这是开发中最臭名昭著的毒瘤！
这样做并没有在当前作用域创建合法的变量，而是将它挂载为了全局对象 (Global Object) 上的一个恐怖属性，这将导致严重的命名污染。一定要养成加上声明前缀的习惯！
