Implementing the Game Logic (编写核心游戏逻辑)

📺 来源：007 Implementing the Game Logic.en.srt 📂 章节：第 07 章

我们已经知道如何捕获按钮点击了。现在，我们要把真正的“血肉”填充进去：如果猜大了怎么提示？猜小了怎么扣分？一直扣到 0 分以后游戏该如何判定结束？

1. 非常重要的概念：状态变量 (State Variable)

在游戏中，玩家起步有 20 分 (Score = 20)。每次猜错扣 1 分。我们该如何实现呢？

❌ 糟糕的做法：从 DOM 读取再写回

有些人会想：“我们先用 document.querySelector('.score').textContent 把网页上的 '20' 读出来存成变量，减去 1 得到 19，然后再写回到网页 DOM 里去更新。”

✅ 专业的做法：维护应用状态 (Application State)

我们千万不能依赖 DOM 来保存数据。DOM 只是用来被动显示的界面！正确的做法是：在 JavaScript 代码顶端，创建一个变量来存储当前分数。这个变量就是所谓的 State (状态)：它握有应用程序当下的全部关键数据。

let score = 20; // 这是一个 State Variable (状态变量)。
// 注意：必须用 let 而非 const，因为它的值会在游戏中不断随扣分而改变。

当判定发生错误时，我们直接在代码里 score = score - 1; 甚至简写为 score--;。计算完毕后，我们再单向地把最新的 score "印"到页面上去。这一原则在未来的 React 框架等现代开发中是重中之重。

2. 分数扣减与胜负判定

如果玩家一直猜错，分数会变成多少？如果不管它，分数甚至会扣成负数，游戏永远不会结束。因此我们需要在扣分前加上一个守卫条件 (Guard condition)：

// 当用户猜测错 (太大或太小时)...
if (score > 1) {
  // 还有命，可以继续扣
  score--;
  document.querySelector('.message').textContent = '📈 Too high!';
  document.querySelector('.score').textContent = score;
} else {
  // 分数扣到了 0 (原来是1扣完了) 或者更低
  document.querySelector('.message').textContent = '💥 You lost the game!';
  document.querySelector('.score').textContent = 0;
}

💡 为什么判断是 score > 1 而不是 score > 0？
因为如果当前已经是最后 1 分了，玩家这把又猜错，此时就应该触发结束分支打印 "You lost"，且将分数定格在 0。如果设为 `> 0`，最后 1 分猜错时程序会把分数扣成 0 然后仍然打印 "Too high!"，直到下一把再点才宣判死亡，体验就不对了。

🧪 学习验证

1. 为什么极力推荐将 `score` 作为 JavaScript 文件顶端的一个变量（State），而不是每次通过 `document.querySelector('.score').textContent` 提取后再减去 1？
A) 因为应用的数据状态应当由代码掌控（Application State），DOM 仅仅只是用来展现结果的画板。依赖 DOM 保存数据会导致程序难以追踪状态。
B) 因为 `textContent` 提取出来的东西无法被转成数字进行减法操作。
👍 正确！ 解析：这是一个极其关键的思想！数据驱动视图。我们的代码作为“大脑”，必须将所有重要数据记录在案（变量中），当数据计算完毕，再发号施令让 DOM（界面）去改变显示。切忌让界面沦为你代码的数据库。
