Memory Management: Primitives vs. Objects

📺 来源：013 / 014 Primitives vs. Objects in Practice.en.srt 📂 章节：第 08 章

🎯 概述

如果说作用域决定了“去哪找变量”，this 决定了“谁在调用我”，那么内存管理回答的就是最底层的物理问题：“我的数据到底存放在内存的哪个角落？”。在 JavaScript 中，基本数据类型和引用数据类型（对象）的存储方式截然不同。理解了这一点，你就能彻底避开“修改了一个变量，另一个变量却跟着莫名其妙变了”的史诗级大坑。

1. 栈 vs 堆 (The Call Stack vs The Memory Heap)

JavaScript 引擎的内存空间被分为两大阵营：

  • 调用栈 (Call Stack)：负责存放那些体积固定、轻量的数据，即 基本数据类型 (Primitives)，如 Number、String、Boolean、Undefined、Null、Symbol、BigInt。它们直接与当前的执行上下文绑定。
  • 内存堆 (Memory Heap)：负责存放那些体积庞大、动态变化的数据，即 引用数据类型 (Objects - 包括对象字面量、数组 Array、函数 Function)。

💡 特例说明：现代 JS 引擎（如 V8）极度聪明。有时候遇到一个长达几万字符的 String，引擎看它太大，可能会悄悄把它扔到“堆”里以优化栈的性能。但作为开发者的宏观心理模型 (Mental Model)，你依然应当坚信：基本类型都在栈里，对象都在堆里。

2. 杀手级概念：对象引用 (Object References)

基本数据类型的拷贝非常简单粗暴：“各自拥有一份独立复印件”。


let age = 30;
let oldAge = age; // 栈里新开辟一块空间存 30
age = 31; // 互不干扰，oldAge 依然是 30

但对于对象，情况就完全不同了——因为对象是存储在内存堆 (Heap) 里的。而我们的变量依然是活在调用栈 (Stack) 里的。栈里的变量是如何跟堆里的对象打交道的呢？答案是：指针（内存地址引用）。

当我们执行 const friend = me; 时，JS 绝没有在堆里复制一个一模一样的对象，它仅仅是把栈里的那个包含十六进制内存地址的卡片复印了一张给了 friend！

🚨 这就是万恶之源： 如果你现在执行 friend.age = 27;。由于 me 和 friend 手里拽着同一张寻宝图（内存地址），它们顺藤摸瓜找过去的都是同一个宝箱（堆里的对象）。所以你改了 friend，也就变相篡改了 me！

3. 浅拷贝 (Shallow Copy) 与 深拷贝 (Deep Clone)

既然直接赋值 = 行不通，我们该怎么真正地克隆一个对象呢？

⚠️ 浅拷贝 (使用 Object.assign 或 展开运算符)

const jessica = {
    name: 'Jessica',
    family: ['Alice', 'Bob'] // 这是一个嵌套对象(数组)!
};

// 使用展开运算符复制:
const jessicaCopy = { ...jessica };
jessicaCopy.name = 'Davis'; // ✅ 这一层没问题

jessicaCopy.family.push('John');
// 💥 灾难：jessica.family 也被污染加入了 'John'！
✅ 深拷贝 (现代绝招 structuredClone)

const jessica = {
    name: 'Jessica',
    family: ['Alice', 'Bob']
};

// 使用 ES 现代原生深拷贝函数:
const jessicaClone = structuredClone(jessica);


jessicaClone.family.push('John');
// ✅ 完美：原对象 jessica 此刻毫发无伤！
// structuredClone 会连同嵌套的数组/对象一起开辟新空间。

为何浅拷贝会出问题？ 因为第一层复制时，遇到数值和字符串这些基本类型，就乖乖复制值；但当它扫到 family 这个属性时，它发现它是个数组（对象），于是它又偷了懒，只把内存地址拷贝过去了！所以深层的对象依然是挂钩在一起的。

（注：以前在没有 structuredClone 的黑暗年代，人们苦逼地要么使用外部库 Lodash 的 cloneDeep，要么用性能堪忧的 JSON.parse(JSON.stringify(obj)) 来实现深拷贝。）

🧪 学习验证

1. 关于 `const` 和对象的结合，为什么 `const myObj = { x: 1 }; myObj.x = 2;` 不会因为 const 而报错？
A) 因为 `const` 锁死的是“位于调用栈里的那个内存地址”。只要你不给 `myObj` 这个变量重新赋一个完全新的对象（即更换内存地址），随便你怎么修改堆里原有对象里面的属性，栈里的那串 16 进制地址本身并没有变！所以它完全合法。
B) 因为 JS 放弃了对对象类型的常量检查。
正确答案：A。这是极为关键的顿悟！const 只能保卫栈内存中的值不可变（对于对象而言，栈里存的就是地址引用）。堆内存中发生什么事，const 根本管不着！
