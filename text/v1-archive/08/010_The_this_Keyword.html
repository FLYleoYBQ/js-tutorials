The this Keyword (`this` 关键字机理)

📺 来源：010 The this Keyword.en.srt 📂 章节：第 08 章

🎯 概述

欢迎来到 JavaScript 里最让初学者（甚至老手）头疼的概念：this 关键字。上几节课我们知道它和环境、作用域链一样，是构成“执行上下文”的三大基石之一。本小节我们将彻底拆解 this 变幻莫测的指向规则。只要记住几个硬核法则，它其实毫无魔力！

🚨 黄金法则：`this` 的指向永远是动态的！它是根据“函数被谁调用的”，在执行的那一瞬间才被赋予的指向值，而不是在代码写好的那一刻决定的！

1. `this` 指向的四大绑定法则

函数的调用方式决定了 this 的命运。日常开发中，我们最常遇到以下四种主流调用场景：

调用场景 (How is the function called?) this 的对应指向 (What does this point to?) 示例解读
1) 作为对象的方法调用
(Method Call)		 👉 指向调用该方法的那个对象
(Object calling the method)		 Jonas.calcAge()：在这里面，this 就会被指向 Jonas 这个对象实体。
2) 作为独立函数裸调用
(Simple Function Call)		 👉 undefined (严格模式下)
或 window (非严格模式下)		 calcAge()：前面没有挂载任何对象或圆点。所以它没有主人，this 就是 undefined。这就是为什么一定要开严格模式防 Bug。
3) 箭头函数
(Arrow Function)		 👉 指向包裹它的外层（父级）普通函数的 this
(Lexical this)		 ⚠️ 箭头函数没有自己的 this！它是个啃老族，它里面的 this 实际上用的是它的父级函数（词法作用域）留下来的 this。
4) DOM 事件监听器
(Event Listener)		 👉 指向触发该事件的 DOM 元素本身 document.querySelector('btn').addEventListener(...)：回调函数里的 this 指向的就是这个 <button> 元素。

（注：后期我们还会学习用 new 关键字实例化类、以及使用 call, apply, bind 方法强行改变 this 指向的高级玩法。本节先攻克这最基础的四点。）

2. 请消除错觉：`this` 绝对不是什么？

为了防止面试题把你绕晕，请死死记住以下两条著名的新手错觉：

  • ❌ 错觉一：认为 this 指向函数自己本身（Function itself）。错！
  • ❌ 错觉二：认为 this 指向函数的变量环境（Variable Environment），以为可以通过 this.内部变量 来访问自己内部的 let 变量。错！绝对不行！

🧪 学习验证

1. 假设有个对象 `const car = { brand: 'BMW', getBrand: function() { return this.brand; } }`。如果我们这么调用：`const func = car.getBrand; func();`，在使用了严格模式下，会发生什么？
A) 顺利返回 'BMW'，因为原来这个函数写在了 car 对象里面。
B) 报错。因为我们把函数提取出来后是裸调用的 (`func()`)，没有前缀对象，严格模式下 this 变成了 undefined，无法读取 undefined.brand。
正确答案：B。完美展示了“this取决于谁调用，而不是写在哪”！虽然方法原本属于 car，但你把它抽出来作为常规函数独立调用了，它就成了没主的孤儿。

2. 为什么在需要用到 `this` 的对象方法内部，我们经常被告知千万不能使用箭头函数？
A) 因为箭头函数没有自己专门的 `this`，它会向上寻找父级作用域的 `this`。由于对象大括号 `{}` 是不产生作用域的，它会直接找到 Global 的 window 去，导致拿到 undefined 或报错。
B) 因为箭头函数执行速度太慢。
正确答案：A。这是后面即将演示的经典坑！箭头函数会直接穿透当前包含它的对象，向外层搜寻 this，这就是常说的词法作用域特性 (Lexical this)。
