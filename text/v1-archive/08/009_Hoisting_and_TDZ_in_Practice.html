2. 函数提升极其引发的灾难 Bug

我们来看一个大型开源项目中都可能犯下的失误。我们要在当前购物车商品为零时，清理系统。但是由于把重要变量置为 var 而引发了致命的 undefined 渗透假值操作。

🚨 毁灭性的 Bug (使用 var)
if (!numProducts) {
    // 因为 numProducts 会被提升但是是 undefined
    // !undefined === true，于是这里不该执的动作被执行了！
    deleteShoppingCart(); 
}

var numProducts = 10; // 即使你明明写了有 10 个！

function deleteShoppingCart() {
    console.log('商品已被全部删除！');
}
✨ DRY 清晰写法 (The Refactored Way)

const numProducts = 10; // 遵循规范：先声明！而且使用 const！

if (!numProducts) {
    // 此时一切逻辑如常运转，如果不为0，则跳过
    deleteShoppingCart(); 
}

function deleteShoppingCart() {
    console.log('商品已被全部删除！');
}
💡 工业界最佳实践原则

1. 永不使用 var。

2. 把大部分变量声明为 const，确有需要修改再用 let，并将所有变量写在环境的顶部。

3. 养成先声明，后调用的顺序习惯。

exercise_hoist.js
💡 参考答案

由于使用 const 接收了箭头函数，这个变量 add 现在处于暂时性死区 (TDZ) 之中。若要实现“在定义之前自由调用”，必须重构为完整的 function 函数声明。

console.log(add(2, 3)); // 正常打印 5

function add(a, b) {
    return a + b;
}

🔧 代码填空

在 ES6 环境中，尝试访问身处在块级域 TDZ 阴影内的 age，会触发特定报错：


const age = 30;
{
    // ________ 取出局部 age，这里发生了 TDZ 报错
    console.log(age); 
    const age = 99; // 上面这行想要读取由于此声明被提升（但停留在TDZ中）的age。
}
💡 答案 
ReferenceError 或者 Cannot access 'age' before initialization
