Regular Functions vs. Arrow Functions (常规函数与箭头函数的终极对决)

📺 来源：012 Regular Functions vs. Arrow Functions.en.srt 📂 章节：第 08 章

🎯 概述

上节课我们刚背熟了 this 的四大法则。但这节课，我们要亲眼见证这四大法则如何在真实的嵌套代码中“互相打架”，导致初学者痛不欲生的 Bug。我们将通过一个极其经典的“对象内部的函数调用”陷阱，来彻底搞清常规函数和箭头函数的本质区别。

1. 对象方法内部的嵌套：`this` 陷阱 🪤

假设在一个对象 Jonas 中，我们有一个方法 calcAge。为了代码高大上一点，我们想在 calcAge 内部再写一个小小的辅助工具函数 isMillennial()，用来判断他是不是千禧一代。

💥 踩坑做法 (The Pitfall)

const jonas = {
    year: 1989,
    calcAge: function() {
        console.log(this); // 这里是 jonas 对象 ✅

        // 在方法内部，再嵌套写一个普通函数
        const isMillennial = function() {
            // 💀 灾难发生！
            console.log(this.year >= 1981); 
        };
        
        // 调用它！
        isMillennial(); 
    }
};

jonas.calcAge();
// 报错：Cannot read property 'year' of undefined!

💥 为什么会报错？引擎怎么想的？

很多人的直觉是：既然 isMillennial() 物理上写在 calcAge 这个方法大括号里，那它的 this 肯定和外壳的 jonas 是一样的吧？

大错特错！回忆上节课的第二法则： isMillennial() 在下面被调用的时候，它是“独立裸调用”的！它的前面没有任何 对象. 前缀！因此，独立裸调用的普通函数，其内部的 this 永远无情地指向 undefined（严格模式下）！

（注：在 ES6 出生以前，老一辈程序员为了解决这个坑，会在外部保存一个 const self = this; 然后在内部用 self.year，但这种做法现在看起来非常笨拙。）

2. 救场英雄：箭头函数 (Arrow Function)

这就是箭头函数大展神威的时刻！箭头函数的设计初衷，不仅仅是为了让你少敲几个 function 字母，更是为了解决这种 this 迷失的痛点。

✨ 优雅做法 (ES6+ 箭头函数)

const jonas = {
    year: 1989,
    calcAge: function() {
        console.log(this); // jonas 对象 ✅

        // ✨ 换成箭头函数
        const isMillennial = () => {
            // ✅ 成功运行！
            console.log(this.year >= 1981); 
        };
        
        // 调用它
        isMillennial(); 
    }
};

jonas.calcAge();
// 输出：true (成功访问到了 jonas.year)

✨ 为什么这招管用？

回顾法则三：“箭头函数没有自己的 this”。当引擎遇到 isMillennial() 内部的 this 时，它发现这是个箭头函数，于是它放弃了给它分配 undefined，转而顺着作用域链向上一层寻找。它找到了它父亲 calcAge 方法上下文里的 this（也就是 jonas 对象本身）。

💡 最佳实践铁律：

  • 如果你要在一个对象里声明最顶层的方法（比如上面的 calcAge），必须用常规 function() {}，否则它依然没有 this 会顺着找到 window 去。
  • 如果你是在方法内部嵌套写辅助函数（或者定时器 setTimeout，或者数组的 map/filter 等回调），请一律使用箭头函数 () => {}，以确保它能完美继承外部包裹它的那个 this！

3. 附带讨论：`arguments` 关键字 (已成为时代的眼泪)

在所有执行上下文里，除了能拿到 this，其实引擎还会偷偷塞给你一个特权变量，叫做 arguments。它是一个伪数组，包含了你在调用函数时塞进括号里的所有所有参数（即使你实际上没提前在函数入参列表里声明它们！）。


// 普通函数：享有 arguments 特权
const addExpr = function(a, b) {
    console.log(arguments); 
    return a + b;
};
addExpr(2, 5, 8, 12); // 虽然只声明了a,b，但arguments里会有[2, 5, 8, 12]这四个数！

// 箭头函数：抱歉，这也是没有的！
const addArrow = (a, b) => {
    console.log(arguments); // 💥 ReferenceError: arguments is not defined
    return a + b;
};

和 this 一模一样，箭头函数也没有属于自己的 arguments 伪数组。了解这一点对于面试防坑很重要。虽然现在有了更强大的 ES6 Rest Parameters (...args) 语法，arguments 已经逐渐被淘汰，但旧代码里仍会经常看见它的身影。

🧪 学习验证

1. 在 `const car = { brand: 'Audi', info: () => { console.log(this.brand); } }; car.info();` 执行后会发生什么？
A) 打印 undefined。因为对象的大括号 `{}` 不是代码块/作用域。箭头函数 `info` 内部没有 `this`，向外找父级作用域，只能找到 Global 环境，拿到了 window.brand，即 undefined。
B) 打印 'Audi'。因为箭头函数是属于 car 这个对象的。
正确答案：A。这是极其经典的错误！千万不能用箭头函数去充当对象首层的“普通方法”，它会直接穿透对象导致 this 丢失！
