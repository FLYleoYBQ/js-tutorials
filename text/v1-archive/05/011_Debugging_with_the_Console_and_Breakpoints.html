🎯 概述

上节课我们探讨了 Bug 的定义和应对策略。纸上谈兵终觉浅，这节课我们要真刀真枪地在代码里追踪两处经典 Bug，并且学习使用前端开发最致命的武器 —— Chrome DevTools 调试器 断点 (Breakpoints)。

1. 利用 Console 查漏补缺

假如我们需要开发一个极简函数：接收用户输入的摄氏度（Celsius），返回对应的开尔文温度（Kelvin）。开尔文的换算公式很简单：摄氏度 + 273。

来看看这段藏有暗雷的代码：

💣 常规输出 (存在隐患)
const measureKelvin = function() {
    const measurement = {
        type: 'temp',
        unit: 'celsius',
        // 模拟从 prompt 弹窗获取温度
        value: prompt('Degrees celsius:') 
    };

    const kelvin = measurement.value + 273;
    return kelvin;
};

// 如果我们在弹窗输入 10，这里会输出多少？
console.log(measureKelvin()); // 🔴 竟然变成了 "10273"！
🛡️ 进阶 Console 战术
const measureKelvin = function() {
    const measurement = {
        type: 'temp', 
        unit: 'celsius', 
        value: prompt('Degrees celsius:') 
    };
    
    // 💡 战术一：不要只 log 局部变量，可以打印出完整的对象！
    console.log(measurement); 
    // 看到控制台里的 value 是个字符串格式的 "10"，我们才恍然大悟！
    
    // 💡 战术二：如果你有超级大的嵌套对象，用表格输出巨清晰！
    console.table(measurement);

    // ✅ 修复：将 prompt 获取的绝对 String 转为 Number。
    const kelvin = Number(measurement.value) + 273;
    return kelvin;
};

💡 拓展锦囊：那些你不知道的 Console：

  • console.log() - 默认的白色日志，平平无奇。
  • console.warn() - ⚠️ 黄色高亮显示，用来抛出潜在风险提示。
  • console.error() - 🔴 红色高亮并附带堆栈追踪，用来模拟最高级别的系统报错。
  • console.table() - 📊 自动把数组或对象格式化生成一个精致的网格表格（强烈推荐）。

2. 步入高阶：Chrome 断点调试 (Breakpoints)

虽然 console.log() 被大家戏称为“史上最坚挺的调试工具”，但在拥有几千行代码和复杂循环的函数中不停地写 log 然后删掉，实在过于笨重。

此时，断点 (Breakpoints) 闪亮登场。它的核心逻辑是：在代码运行的半空中按下“时间暂停”键。此时宇宙万物静止不动，你可以随意查看那一瞬间所有变量的值。

具体操作手法：

  1. 在 Chrome 浏览器中按下 F12 或者右键选择 检查(Inspect) 打开开发者工具。
  2. 在最顶部的菜单栏点击 Sources（源代码） 面板。
  3. 在左侧文件树中找到并选中你写好的 script.js 文件。
  4. 在代码编辑区域的左侧行号数字上点一下。那里会出现一个醒目的蓝图标记（早先是红点），这就是你的“结界（断点）”。
  5. 刷新页面触发代码。页面执行到这行时会瞬间挂起停顿（Paused in debugger），右下方会展示出当时的全局和局部变量快照。
  6. 点击悬浮控制条中的 ➡️ Step over next function call (单步跳过)，可以让代码像挤牙膏一样，每次只精确往下执行一行。

3. 循环内部捉虫与 debugger 指令

前面两节课我们徒手写了一个计算最高温和最低温振幅的函数。假设这次粗心的写手在初始化 max 和 min 时自作聪明地使用了 0。

index.js

当我们执行代码时，发现 min 最终的值竟然匪夷所思地定格在了初始值 0 上，而不是数组里的最小值 1。

如果你使用我们在 Sources 面板里打在 if (curTemp < min) min = curTemp; 这行代码的断点进行逐行执行(Step Over)监视，真相瞬间大白：我们传入的数组里最低温度是 1。因为我们一上来就把最小值钦定为 0（低于所有数字），导致这句 if 语句的条件 (1 < 0) 永远不可能判断为真，因此也就永远不会刷新最低温记录。

⌨️ 懒人必看的魔法咒语 "debugger;"
每次都在浏览器里去找文件、点行号嫌麻烦？直接在 JS 代码源文件你想暂停的地方，写下大写的 debugger; 这句霸道的内置保留词！浏览器只要不小心读到这个拼写，就算你没点开 Sources 面板，它也会像受到惊吓一样强行自动打开调试器停下来！
(一定要注意！发布交给老板验收的版本时，千万别把代码里的 debugger; 忘了删掉。)

❓ 理解检测

1. 下列关于浏览器断点调试的说法，哪一个是完全正确的？
A) 每次必须都在 Elements 标签页下操作，才可以单步执行 JavaScript。
B) 直接在你的 .js 物理文件中输入专门的 `debugger;` 语句即可命令浏览器强行挂起并召唤出调试器界面。
C) 断点调试时必须通过 console.log 来辅助观看变量情况。
B 是正确的选项。JavaScript 的内置保留字 `debugger` 可以直接替代在 Chrome Sources 面板右键点点点的繁琐流程，非常提效。
