What's the DOM and DOM Manipulation

📺 来源：004 What's the DOM and DOM Manipulation.en.srt 📂 章节：第 07 章

🎯 概述

欢迎来到令人兴奋的地方！在这一节，我们将使用 JavaScript 与网页进行真正的交互，专业术语叫做 DOM 操作 (DOM Manipulation)。我们将揭开 DOM 的神秘面纱，了解它的树状结构，并澄清一个极其普遍的新手误区。

1. 什么是 DOM？它的树结构是怎样的？

DOM (Document Object Model，文档对象模型) 是 HTML 文档的结构化表示形式。简单来说，DOM 就像是 HTML 和 JavaScript 之间的一座桥梁，它允许我们使用 JavaScript 去访问和修改 HTML 元素及 CSS 样式（比如改变文本、修改属性、变换颜色等）。

当浏览器加载 HTML 页面时，它会自动在幕后创建这个 DOM。DOM 的结构是一棵倒置的“家族树”：

flowchart TD Doc[document 对象
(DOM 的入口点)] --> HTML[html
(根元素)] HTML --> HEAD[head] HTML --> BODY[body] HEAD --> TITLE[title] BODY --> SECTION1[section] BODY --> SECTION2[section] SECTION1 --> H1[h1] SECTION1 --> P[p] P --> A[a 链接] style Doc fill:#f7df1e,color:#000 style HTML fill:#8be9fd,color:#000 style HEAD fill:#50fa7b,color:#000 style BODY fill:#50fa7b,color:#000
  • document：位于树的最顶端。它是所有 DOM 操作的入口点（这也是为什么我们总是写 document.querySelector(...)）。
  • 节点关系：在这棵树里，每个 HTML 标签都是一个“对象”（或者叫节点 Node）。我们常常用 父元素 (Parent)、子元素 (Child)、兄弟元素 (Sibling) 来描述它们之间的亲戚关系。
  • 除了元素节点，DOM 树里甚至还包含纯文本节点、注释节点等，DOM 必须是一份百分百忠实于 HTML 原文档的完整倒影。

2. 澄清误区：DOM 根本不是 JavaScript 的一部分！

这是一个连很多老手都搞错的惊天秘密：

🚨 真相大白：诸如 document.querySelector() 这样的 DOM 方法和属性，其实根本不属于 JavaScript 语言本身！

我们在前面学过，JavaScript 只是 ECMAScript 规范的方言，它的核心语法库里根本没有这些操作网页的东西。那它是怎么工作的呢？

答案是：Web APIs。

Web APIs 是浏览器内置的、用 JavaScript 编写的库。浏览器大方地把这些 API 开放出来，让我们的 JavaScript 代码可以直接调用。不仅仅是 DOM，像后面会学到的 Timers (定时器)、Fetch API (网络请求) 等等，全都是浏览器提供的 Web APIs。

🧪 学习验证

1. 下列关于 DOM 的说法中，哪一项是绝对正确的？
A) DOM 是 JavaScript 语言核心规范 (ECMAScript) 中的一部分机制，只要能跑 JS 的地方（比如 Node.js）就一定有 DOM。
B) DOM 是一套由浏览器提供的 Web API 接口，用于将 HTML 文档映射为树状对象，以便 JS 能修改网页。
正确答案：B。DOM 属于浏览器环境宿主提供的 Web API，脱离了浏览器的纯运行环境（如 Node.js）是没有 `document` 对象的。

2. 为什么我们在操作网页前，首先要通过 `document` 对象进行查询？
A) 因为 `document` 对象不仅是特殊对象，更是整棵 HTML DOM 树的顶级入口点 (Entry Point)。不通过它，JS 就像没钥匙进不了家门。
B) 因为 `document` 代表了浏览器整个窗口，包含了浏览器的地址栏和历史记录等功能。
正确答案：A。`document` 专门负责表示当前加载的 HTML 页面本身及其结构；而代表整个浏览器窗口的是另一个叫 `window` 的对象。
