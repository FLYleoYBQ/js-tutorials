🎯 概述

上节课我们提到，每个执行上下文都会分配一个 this 变量。它到底代表了什么对象？这完全取决于该函数是如何被调用的，与它是如何被编写的无关。今天通过四组真实代码实验，一次性看透 this！

1. 全局和普通函数中的 this

首先，在全局最高层面上（不包裹在任何函数内），this 就是大写的 Global Object。在浏览器环境下，它就是 window。

但在普通的函数里，情况就有变化了：

this_in_funcs.js
⚠️ 严格模式防线

在普通函数内部，如果不是通过对象调用，this 默认是 undefined（在使用 `'use strict'` 时）。如果没开严格模式，JS 引擎会“好心办坏事”地把它设为全局 Window 对象，引发难以追查的 Bug！

2. 箭头函数中的 this (Lexical this)

箭头函数根本就没有自己的 this 关键字！当你在箭头函数里使用 this 时，它会去它的外层作用域（也就是声明它的父级词法环境）“借”一个 this 过来使用。我们称之为 Lexical this。

3. 对象方法与 Method Borrowing

这是 this 最常见也是最有用的形态！当一个函数作为对象的方法被调用时，this 将指向调用它的那个对象！

👤 Jonas 对象调用
const jonas = {
    year: 1991,
    calcAge: function () {
        console.log(this);
        return 2037 - this.year;
    }
};

jonas.calcAge(); 
// 输出 46。因为是谁调用的？是 jonas!
// 所以内部的 this.year 等于 jonas.year!
🔄 Matilda 借用方法 (Method Borrowing)
const matilda = {
    year: 2017
};

// 我们可以直接把 jonas.calcAge 的内存引用抄送给 matilda
matilda.calcAge = jonas.calcAge;

// 现在是谁调用的？是 matilda!
matilda.calcAge(); // 输出 20
// this.year 变成了 matilda.year!
💡 **核心口诀**：看 this，别看函数是在哪里写好的，要看此时此刻这行代码到底是谁点了它（谁调用的它）！调用对象.方法名()，这个 调用对象 就是 this。

1. 当运行 `user.calcAge()` 时，箭头函数 `printScope` 中打印出来的 this 是什么？

const user = {
    firstName: "Jonas",
    calcAge: function() {
        const printScope = () => {
            console.log(this.firstName);
        };
        printScope();
    }
};
A) 打印出 "Jonas" 因为箭头函数的 this 就是外层 calcAge 方法的 this (user 对象)
B) 打印出 undefined 或者抛错，因为箭头函数没有 this
C) 打印出 Window 对象的某属性

🔧 代码填空

我们有一个独立的函数 greet，想要将它的 this 指向到 person 对象并执行。除了使用我们之前提到的 Method Borrowing 修改原对象，在 JS 中其实还有个内置函数可以临时改变 this。它的名字叫 call：


const person = { name: "Alice" };
function greet() {
    console.log(`Hello, ${this.name}!`);
}

// 补全代码：让 greet 在执行时立即绑定 this 为 person
greet._______(person); // 输出 "Hello, Alice!"
💡 答案 
greet.call(person); // 或者是 apply
