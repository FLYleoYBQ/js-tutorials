Execution Contexts and The Call Stack (执行上下文与调用栈)

📺 来源：005 Execution Contexts and The Call Stack.en.srt 📂 章节：第 08 章

🎯 概述

假设你的代码编译完毕准备运行，JS 引擎究竟是如何知道运行到哪一行的？如果出现了函数嵌套调用，引擎是如何保证不迷路的？本节我们将揭晓引擎内部的“行车记录仪”：执行上下文 (Execution Context) 与 调用栈 (Call Stack)。

1. 什么是执行上下文 (Execution Contexts)？

当 JavaScript 代码编译完成后，引擎会立刻为其创建一个 全局执行上下文 (Global Execution Context)。它是用来执行代码的环境（你可以把它想象成一个包含了执行代码所需所有材料的包裹或者箱子）。

📦 生活类比：假设我们要吃比萨。你不能让比萨飘在空中吃，必须找一个“桌子（环境）”，桌子上要有“餐具（变量环境）”，还有“谁买单（this 关键字）”。执行上下文就是这张桌子。

引擎在运行时的第一法则是这三步：

  1. 为不在任何函数内部的顶层代码 (Top-level code) 创建 全局执行上下文。
  2. 执行这段顶层代码。
  3. 每当调用一个函数时，引擎会立刻为该函数创建一个属于它自己的全新执行上下文。

一个执行上下文里面到底装了什么？

每个上下文包裹里包含三大核心物件（这在随后的几节课会反复考到！）：

🚨 关键考点（面试常客）：请死记硬背！箭头函数 (Arrow Functions) 的执行上下文里，没有自己的 arguments 对象，也没有自己的 this 关键字！ 它们是借用离自己最近的普通父级函数的。这就是箭头函数的命相所在。

2. 调用栈 (The Call Stack) 是如何运作的？

我们讲了每次调用函数就会产生一个上下文包裹。那如果函数 A 调用函数 B，函数 B 又调用函数 C 呢？引擎要如何保证记住执行的顺序，并且在 C 执行完后准确退回到 B？

答案是：调用栈 (Call Stack)。这是 JS 引擎用来跟踪程序执行状态的数据结构（LIFO：后进先出栈）。不管什么代码，必须在调用栈的最顶端（Top of the stack）才能被执行。

让我们来人肉单步调试一段代码的调用栈变化：


const name = 'Jonas'; // 顶层代码

const first = () => {
    let a = 1;
    const b = second(7, 9); // 函数调函数
    a = a + b;
    return a;
};

function second(x, y) {
    var c = 2;
    return c;
}

const x = first(); // 触发全栈！

原理解析追踪：

  • 1. 引擎一启动，先压入Global（黄底）。它是万物的基石。
  • 2. JS 单线程向下扫描，最后一行发现调用了 first()，立马为它创建崭新的蓝底上下文并压入栈顶 (Push)。此时，蓝底是 Active 状态，黄底 Global 被迫暂停 (Paused)。JS 单线程永远只处理栈顶。
  • 3. first 运行到一半，惊呼又调用了 second()！引擎立马为其创建绿底的上下文并压栈登顶。此时蓝色和黄色全被封冻暂停。
  • 4. 绿色的 second 执行到 return c; 完成任务，绿底上下文瞬间被弹出栈并销毁 (Popped off)。控制权完美交还给下方的蓝底 first() 上下文，它苏醒后继续执行剩余加法。
  • 5. 蓝底也完成任务 return。整个程序只剩下黄底的 Global，直到你关闭浏览器 Tab 页，连它也被摧毁。

💡 总结引申：这就是为什么很多人说 JS 代码运行在“调用栈”里（确切地说，是运行在位于栈顶的执行上下文里）。由于栈结构永远不会乱，JS 引擎就像拿了一份永不丢失的 地图 (Map)，随时知道自己身在何处，该回到哪里。

🧪 学习验证

1. 下列关于“箭头函数”执行上下文包裹的说法，最致命的（也是最正确的）不同点是什么？
A) 它没有属于自己的 `arguments` 对象，也没有指向自己的 `this` 关键字。
B) 它无法被推入调用栈 (Call Stack) 中执行。
C) 它没有自身的变量环境 (Variable Environment)，里面的变量全是对外层的引用。
正确答案：A。这是无数面试和复杂 bug 的出处！箭头函数有它自己声明内部变量的 Variable Environment，也能压入调用栈。但它丧失了普通函数拥有的 this 主动权和 arguments 对象特权，只能“啃老”去向它的父级要。

2. 为什么 JavaScript 被称为“单线程”语言，这与调用栈有什么关系？
A) 因为它只能用到 CPU 的一个物理核心。
B) 因为它没有对象，只有一个大包厢存放变量。
C) 因为它的核心只有一个调用栈 (Call Stack)，同一时刻只有栈顶端的那一个上下文 (Context) 在执行，其余都在排队或暂停。
正确答案：C。JS 在运行时只有一个调用栈（主厨），一次只能炒一口锅里的菜（栈顶那个活跃的 Context）。一旦遇到嵌套函数调用，下方的原功能必须乖乖立正暂停，无法“同时处理”。
