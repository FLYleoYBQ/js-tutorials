The JavaScript Engine and Runtime (JS 引擎与运行时架构)

📺 来源：004 The JavaScript Engine and Runtime.en.srt 📂 章节：第 08 章

🎯 概述

你知道当你写下一段 JS 代码到它真正在浏览器中跑起来，中间经历了什么吗？本节课我们将深入剖析 JS 引擎的黑盒（以 Google V8 为代表），揭秘 JIT 编译和抽象语法树 (AST)。随后，我们会将视线拉远，来看涵盖了引擎、Web API 及事件循环的庞大 运行时 (Runtime) 架构图。

1. JavaScript 引擎是怎么工作的？(JIT)

经常有人说“JavaScript 是一门解释型语言”。这在 15 年前是正确的，但放到现在完全错误。如果现代复杂的单页应用还慢吞吞地一行一行解释执行，用 Google Maps 拖拽地图时恐怕卡得像看 PPT。

现代引擎（如 Chrome 的 V8）使用的是 即时编译 (Just-In-Time Compilation, JIT)。

引擎处理步骤拆解

  • 解析 (Parsing)：引擎先读代码，将其拆分为有意义的片段，然后组装成 抽象语法树 (AST)。注意：AST 仅仅是代码的内部数据结构表示，和我们在控制台看到的 DOM 树没有任何关系！
  • 编译 (Compilation)：获取 AST，并在一瞬间将其编译为计算机 CPU 认识的机器码 (`010101`)。
  • 执行 (Execution)：机器码被立刻扔进调用栈 (Call Stack) 中执行。
  • 优化 (Optimization)：魔法时刻！为了让代码光速启动，引擎一开始生成的是极其粗糙、未优化的机器码。而在后台的秘密线程中，引擎会一边看着你的代码跑，一边持续不断地将它重新编译为更优化的版本，并在不打断主线程的情况下完成“热替换”！这就是 V8 引擎能如此之快的原因。

2. JavaScript 运行时架构 (Runtime)

引擎只是心脏。但要让一个 JS 程序在浏览器里活过来，还需要一个巨大的容器包装好所有基础设施，这个容器就是 运行时 (Runtime)。

运行时架构核心成员

  1. JS 引擎：负责执行 JS 代码（包含内存堆存储对象、调用栈执行指令）。
  2. Web APIs：DOM 操作（`document.querySelector`）、定时器（`setTimeout`）、控制台输出（`console.log`）...等等，它们根本不是 JavaScript 语言的一部分！ 它们是浏览器用 C++ 写的附加功能，直接通过 window 全局对象暴露给 JS 引擎调用。
  3. 回调队列 (Callback Queue)：专门收容那些因为异步事件触发而排队等待执行的回调函数（例如给按钮挂载的 onClick 函数）。
  4. 事件循环 (Event Loop)：它是整个非阻塞架构的指挥官！它时刻死盯着 **调用栈** 和 **回调队列**。如果发现调用栈空了，就把回调队列里排在第一名的函数一把抓进调用栈里执行。这就是这门语言永不卡死的奥秘。

💡 提示：这也是为什么不仅浏览器可以跑 JS。Node.js 也有自己的一套运行时，只不过它没有了浏览器的 Web APIs (没有 DOM)，而是替换成了 C++ 绑定和线程池等后端武器。

🧪 学习验证

1. JS 引擎中的 AST (抽象语法树) 和前端的 DOM 树有什么关系？
A) AST 是 DOM 树的旧版本称呼。
B) 毫无关系。AST 仅仅是引擎用来理解并编译 JS 源代码的数据格式。
C) 引擎通过将 AST 渲染到屏幕上来生成 DOM 树。
正确答案：B。这是一个常见考点。AST (Abstract Syntax Tree) 只是把 JS 代码字符串拆成语法对象树的过程，用于后续编译翻译机器码，与处理 HTML 节点的 DOM API 没有任何交集。

2. `document.querySelector` 和 `console.log` 是 JavaScript 语言的核心特性吗？
A) 不是，它们是浏览器提供的 Web APIs，被挂载到 JS 引擎可访问的运行环境中。
B) 是的，没有它们 JavaScript 语言本身就不完整了。
正确答案：A。如果你离开了浏览器环境去写裸的 JS（或者刚诞生时的 Node.js），你是根本不可能能够直接操作 document 的。它们是寄宿环境（如浏览器）提供给引擎把玩的外部接口。
