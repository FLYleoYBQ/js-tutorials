Object References in Practice

📺 来源：014 Object References in Practice_ Shallow vs. Deep Copies.en.srt 📂 章节：第 08 章
📌 知识脉络
  • 前置知识：调用栈(Call Stack)、内存堆(Heap)、引用类型。
  • 核心突破：如何用代码彻底防范变量复制过程中“互相指引、同归于尽”的灾难。理解浅/深拷贝！

🎯 概述

当我们在日常开发中对一个 Object 使用等于号 = 来赋给另一个变量时，我们仅仅是在转移遥控器，而没有增加新电视！今天我们将通过一系列实战例子，展示如何做 Shallow Copy (浅拷贝)，以及引入现代 JavaScript API 解决 Deep Copy (深拷贝) 的终极难题。

1. 变量直接赋值引起的引用陷阱

我们有一名名为 Jessica 的用户婚后改名了。我们在内存里创建了两个变量指向她，结果引发了灾难。

reference_trap.js
控制台输出将显示在这里...

由于它们是在 Heap 中指向同一个内存块。修改 `marriedJessica` 必然会导致 `jessica1` 也被修改。这在业务逻辑上是毁灭性的！

2. 基础修复方案：Shallow Copy 浅拷贝

要真正建立一个全新的独立对象，我们可以使用 Object.assign() 或者是解构展开运算符 {...obj}。

👤 Object.assign (老式但是可靠)
const jessica2 = {
    firstName: 'Jessica',
    lastName: 'Williams',
    age: 27
};

// 合并目标是一个空对象 {}，然后填充来源属性
const jessicaCopy = Object.assign({}, jessica2);
jessicaCopy.lastName = 'Davis';

console.log('原始:', jessica2.lastName); // 成功保留 Williams！
console.log('拷贝:', jessicaCopy.lastName); // 变为了 Davis
✨ 语法糖展开符 {...obj} (现代偏好)
const jessica2 = {
    firstName: 'Jessica',
    lastName: 'Williams',
    age: 27
};

// 使用拓展运算符直接拆包再包装，创建一个新对象
const jessicaCopy = { ...jessica2 };
jessicaCopy.lastName = 'Davis';

console.log('原始:', jessica2.lastName); 
console.log('拷贝:', jessicaCopy.lastName);
⚠️ 浅拷贝的致命盲区

之所以叫它浅拷贝。是因为这种复制指发生在第一层级。如果 Jessica 对象里面还嵌套了一个小对象，比如叫做 `family: ['Alice', 'Bob']` 数组，那么这个 `family` 内部并没有被复制产生全新的块！被 `Object.assign` 复制过去的，仍然是一个长长的内存遥控器引用！这就是我们要进入下一环节的原因。

3. 进阶修复方案：Deep Copy 深拷贝

如果你要修改的是最内层的 family 数组。我们必须采用能把所有嵌套层级全部斩断然后完全复刻的新方法：structuredClone() 是现代浏览器中的原生救星。

下面的代码使用展开运算符 ... 创建新对象，但是修改数组时引发了连带反应。请阅读后修改 clonePerson 的复制方法，让一切正常运行。

exercise.js
💡 参考答案

因为 skills 是一个引用类型的数组，浅拷贝只拷贝了外层对象，所以里面共享同一个数组！

// 使用最新函数
const clonePerson = structuredClone(person1);
// 或者如果由于环境限制不支持，在老代码中常看到:
const clonePerson = JSON.parse(JSON.stringify(person1));
