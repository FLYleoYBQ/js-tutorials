🚩 数组的天然短板

截至目前我们见识了威力强大的数组 (Arrays)。它可以将多个数据归拢在同一面旗帜下，但是，它存在一个非常致命的设计局限——你没法为数组里面的元素贴上具体的身份标签（Name）！

数组模式下的无奈：只能按次序死记硬背
const jonasArray = [
    'Jonas',         // ← 这是啥？哦，名字。
    'Schmedtmann',   // ← 这是啥？姓氏。
    2037 - 1991,     // ← 这是算数。
    'teacher',       // ← 职业。
    ['Michael', 'Peter', 'Steven']
];

当我们回头来抓取某个属性时，我们只能苦兮兮地回忆：“Jonas 的姓氏到底塞在了第二个位置（1索引），还是第三个？” 数组只认识元素的出场顺序（数字索引），不认识它们存在的意义（语义名称）！

🌟 主角登场：对象 (Objects)

为了完美解决这个问题，JavaScript 献出了它乃至整个语言宇宙中最底层、最核心无敌的第二大数据结构——对象 (Objects)。

在对象里，我们赋予每一个值对应的钥匙标签。这种配对模型叫：键值对 (Key-Value pairs) 或是通称为属性 (Properties)。

这并不是大括号 {} 第一次在 JavaScript 舞台上亮相，这之前它用来包裹 if/else、循环等 代码块(Code Block)。但在这里，它是用来雕刻出一条全新的对象数据底座。在构建对象时，我们用 : (冒号) 分割键与值，并用 , (逗号) 切割不同的属性行（和数组同理）！

⚖️ 数组 vs 对象的根本哲学差异

现在你手中有了两把超级瑞士军刀，你需要知道什么时候掏出哪一把：

📦 数组 (Arrays) [] 📂 对象 (Objects) {}
数据核心特性 必须通过严格次序建立的秩序。顺序如同铁律，0位, 1位, 2位 不容闪失。 彻底的无序化 (Unstructured)。在对象里，你先写 age，还是先写 job，提取时的数据抓取没有任何不同！
数据抓取方式 依赖 数字索引 (Order numbers)。 依赖 明文属性名 (Property names)。
最完美的使用场景！ 存放排列好的、同构的数据流水线序列 (比如气温数据列表 [23, 11, 44]，按顺序轮流读取)。 存放某个独特个体的全方位且错综复杂的描述 (比如构建一个"玩家"实体，有级别、金钱、外观)。

既然对象是彻底跨越了顺序的局限，那么当我们下一次想要获取里面精准到任意标签的数据时，该怎么做呢？我们将在下节课见证！
