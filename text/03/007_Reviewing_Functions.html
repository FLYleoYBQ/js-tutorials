🎯 概述

为了确保你在进入实战挑战前完全理解，这节课我们总结前两节的内容。我们将探讨为什么两个同名参数在不同函数里不会“打架”，并揭示 return 关键字隐藏的“立即退场”属性。

1. 同名参数的独立性

在跨函数调用时，很多人看着同名的 birthYear 变量可能会晕掉。这里有一个核心真相：参数（Parameters）就像是每个函数自己的“私人局域网”，彼此之间互不干扰。

scope.js

如上所示，尽管两个函数都有一个名为 birthYear 的变量，但它们就像两座不同写字楼里都叫“会议室A”的房间一样，虽然名字一样，物理上毫不相干。这保证了各函数的自我隔离。

2. Return 语句的截断执行特性

return 不是简单地输出数据那么简单。它还有一个非常霸道的特权：终止函数。一旦执行到 return 那一行，函数就像被拉下了电闸，后面的代码将永远不被执行！

return-demo.js

🔍 执行追踪：
如果你把 console.log() 移到了 return 之后，控制台将寂静如迷。因此如果想记录日志，千万记得安排在函数“退场”之前。

3. 函数机制全景总览

最后，让我们通过图表将所学过的三种函数体系画一张全景鸟瞰图：

📊 三大函数体系对比：
函数类型 核心写法 关键区别 / 适用场景
函数声明 (Declaration) function myFunc() {...} 可以提前调用(Hoisting)。经典传统写法。
函数表达式 (Expression) const myFunc = function(){...} 变量绑定，不可提前调用。逻辑严谨结构清晰推荐。
箭头函数 (Arrow) const myFunc = () => {...} 省略大量关键字，适合简短单行工具函数，自带隐式返回。由于没有独立的 this 绑定，不可滥用。
无论是哪一种，它们共有的骨架就是：接收参数（Parameters）作为输入 → 函数体加工计算（Body） → 通过 `return` 抛出返回值输出！

❓ 理解检测

1. 下图的代码运行后，会打印字符串 `"我是最后一行"` 吗？ 
function test() {
    return '完成';
    console.log('我是最后一行');
}
test();
A) 会，因为它是写在函数体内的正常语句。
B) 会，甚至会比 '完成' 更早输出。
C) 绝不会。因为代码执行到 return 后会立刻退出该函数，剥夺其后的任何执行权。
解析： C 是正确的。Return 是终极大招，一旦执行它，该函数的调用就当场杀青谢幕了，所有后续语句全部变成不会被触碰的空气代码。
