📦 为什么要用数组？

编程在绝大多数时候都是与数据打交道。当我们只有两三个数据时，声明三个变量 friend1, friend2, friend3 还可以接受。可是，如果我们有 500 个用户的名字，需要创建 500 个独立变量吗？显然这不可能！

这就引出了 JavaScript 中最核心的两大数据结构之一：数组（Array）。（另一个是对象，我们稍后会讲）。

数组就像一个有无数个格子的神奇快递盒，我们可以把所有数据统统打包放进去，并且每个格子都有一个属于自己的“编号”。

🕵️‍♂️ 原理揭秘：用 const 也能修改数组？

我们除了读取数组元素，也可以更新（覆盖）数组里的元素。例如由于某些原因，我们不和 Peter 玩了，我们要修改他的位置换成 Jay：

const friends = ['Michael', 'Steven', 'Peter'];
friends[2] = 'Jay';
console.log(friends); // ['Michael', 'Steven', 'Jay']

⚠️ 等等！这里有破绽！
你可能会问：“Jonas，你上一章才说过被 `const` 定义的变量是绝对不可变 (immutable) 的，这里数组 `friends` 也是被 `const` 定义的，凭什么我能随意改它的元素？”

底层真相揭秘 (Behind the Scenes)：
只有原始数据类型 (Primitive values，如字符串、数字) 才是完全死板的。而数组不属于原始数据类型！在内存里，`const` 锁定的只是数组所居住的那栋楼的“物理地址”。至于在楼里面你怎么给房间搞装修（换掉某个元素），JavaScript 完全不管！除非你要把这栋楼整个炸掉换一栋（例如用 `friends = ['Bob', 'Alice']` 进行完全重写），那才会被 `const` 判定为非法操作！我们会在后期高级理论章节对内存进行超级大盘底揭秘。

绝不要试图用数组自己去进行做算术运算运算（例如 `[1990, 1991] + 10`），那只会得到一团被强制转换为字符串的乱码：`"1990,199110"`。
