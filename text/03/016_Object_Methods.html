🛠️ 方法：当数据成为动词

如果说 firstName 或者 age 是用来描述一个对象的静态“名词”，那么对象是否能够自己装配能够主动运转的“动词引擎”呢？

回忆一下前几节课的宇宙真理：函数(Function) 本质上也只是一种价值形态 (Value)。既然它是一个可以随意拿捏的值，这也就意味着任何对象里的键值对，其 Value 的部分完全可以丢一团函数进去！这就是传说中的——方法 (Method)。

任何依附于对象的函数，都被统称为：方法。

const jonas = {
    firstName: 'Jonas',
    birthYear: 1991,
    // 看这里！分配了一个完整的函数表达式！
    calcAge: function(birthYear) {
        return 2037 - birthYear;
    }
};

// 调用的姿势也是我们极其熟悉的：
console.log(jonas.calcAge(1991));

注意：在这里你必须使用函数表达式 (function expression)。如果你胆敢违规使用 function calcAge() {...} 这种带名字的函数声明，将会得到极其严厉的 Syntax 面壁思过红牌大礼包。

🤖 this 关键词：对象的自我意识

细看上面的代码其实大有毛病：调用计算时，为什么还要一遍遍传入 1991 ？Jonas 对象的内部早已白纸黑字写好了属于自己的 `birthYear: 1991`。这违背了极度神圣的 DRY 原则 (Don't Repeat Yourself)！万一数据改成了 1992 呢？我们要手动在全宇宙找寻这堆散落的代码吗？

为解决这等蠢事，JavaScript 特派了一个无敌指针变量进驻所有方法体内：this 关键字。

this 指针指向什么？永远指向正在召唤这个方法的源头主宰对象 (The object calling the method)。

🧬 终极演化：内部缓存的产生

如果业务上有三个模块都需要获得 Jonas 的年龄，连续呼叫 `jonas.calcAge()` 三次，就意味着你的电脑必须苦哈哈地反复做 3 次数学减法。

更加优雅且节约算力的方法是：在首次运算结束后，借用伟大的 this 顺手把结果藏到对象的一个全新标签中固化下来！这也是商业级代码的常见思路：

❌ 原始粗暴运算 (反复耗电)
calcAge: function() {
    return 2037 - this.birthYear; 
}
// 连叫三次：
console.log(jonas.calcAge());
console.log(jonas.calcAge());
console.log(jonas.calcAge());
✅ 终局缓存思维 (计算一次)
calcAge: function() {
    // 顺手给当前对象烙印一个固化属性 this.age
    this.age = 2037 - this.birthYear;
    return this.age;
}
// 先驱动一次机器引擎...
jonas.calcAge();
// 以后再抓取，全凭顺手拿缓存死数字！极速！
console.log(jonas.age); 
console.log(jonas.age); 
console.log(jonas.age);

🤫 惊天大揭秘：数组方法从何而来？

我们上一节课大讲特讲 “数组有专属的 push()、pop() 等神奇的操作方法”……
现在你刚学会原来这就是“对象身上的 Method”而已……这就破案了！

原来，所谓的数组 (Arrays)，在 JavaScript 最深不见底的底层本质上，不过是一个批着马甲的特殊高阶对象 (Objects)！

这也是为何阵列同样配有 .length 属性甚至能挂上千奇百怪方法的终极原因！这个惊人的核心原理我们在课程偏后期的工作原理深入章节中全盘托出。
