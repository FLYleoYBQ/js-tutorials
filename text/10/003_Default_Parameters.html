默认参数 (Default Parameters)

📌 知识脉络
  • 前置知识：短路逻辑（Short-circuiting）、函数调用
  • 后续扩展：解构与复杂参数处理、ES6 高级写法

🎯 概述

有时候为函数设置默认参数非常有用，这样在不需要改变默认值的情况下，就不必每次手动传入所有参数。本小节带你掌握 ES6 默认参数（Default Parameters）的优雅写法、动态计算机制，以及如何巧妙跳过中间参数。

1. 默认参数的演进：从 ES5 到 ES6

我们以一个虚构的航空公司航班预订函数为例。如果你想为未传递的参数提供默认值（比如默认 1 名乘客，默认价格 199），在 ES6 出现前，我们需要利用逻辑或 || 运算符的短路逻辑（Short-circuiting）来实现。但现在 ES6 允许我们直接在参数列表中定义默认值！

🚨 初版冗余写法 (ES5 样板代码)
const createBooking = function(flightNum, numPassengers, price) {
  // ES5 时代的经典写法：如果参数是 falsy 值 (即 undefined)，则赋予默认值
  numPassengers = numPassengers || 1;
  price = price || 199;

  const booking = {
    flightNum,
    numPassengers,
    price
  };
  console.log(booking);
};
✨ DRY 重构写法 (ES6 优雅新法)
const createBooking = function(
  flightNum, 
  numPassengers = 1, 
  price = 199
) {
  // 直接在参数列表处理，告别函数体内的杂乱逻辑！
  const booking = {
    flightNum,
    numPassengers,
    price
  };
  console.log(booking);
};

默认参数的高级之处在于：默认值不一定是写死的静态数据！它可以是包含表达式甚至引用其他参数的动态计算结果。

⚠️ 严格有序解析
需要注意的是，JavaScript 在处理默认参数时，是按顺序解析的。如果你在 numPassengers 定义前就在其他参数的默认值里引用了它，就会抛出 ReferenceError 错误，因为它还不存在！

3. 巧妙跳过被设置默认值的参数

在传参时，如果我们只想改变第三个参数的值，而第二个参数保持默认值，我们不能通过"留空"跳过参数。因为 JavaScript 传参严格依据位置对齐。

要想跳过前面的默认参数，标准的技巧是传入 undefined。因为对于参数解析器来说，传入 undefined 就等同于"什么都没传"，引擎会自动激活对应的默认参数。

🧪 学习验证

❓ 理解检测

1. 下面这段代码的输出结果是什么？

const demo = (a = 10, b = a * 2, c = b + a) => console.log(c);
demo(5, undefined, undefined);
A) 30
B) NaN
C) 15
正确答案: C。传入 5 赋给 `a`。`b` 收到了 `undefined`，所以触发求默认值 `b = a * 2 = 5 * 2 = 10`。`c` 也收到了 `undefined`，对应求默认值 `c = b + a = 10 + 5 = 15`。
2. 为什么在 ES5 的年代里，通过 `numPassengers = numPassengers || 1;` 设置数字 0 的默认参数有时会带来 bug？
A) 因为 JavaScript 不支持逻辑或运算符
B) 因为 `0` 是一个 falsy 值，即使你真的想传 `0`，这种短路写法也会强行覆盖为你设置的默认值 1
C) 因为 0 加任何数运算会抛出异常
正确答案: B。这是 ES5 "逻辑或短路"赋初值法最大的痛点。如果用户有意识地传入了 0 或者空字符串 `""`，由于它们被判定为 false，依然会被 || 吞噬并覆盖。而 ES6 原生默认参数仅在传入 `undefined` 时才会触发默认值，完美解决了这一误伤问题。
