Coding Challenge #2 (终极闭包考验)

📺 来源：014 CHALLENGE #2.en.srt 📂 章节：第 10 章

前言：这是关于函数的最后一个编程挑战。这个挑战的代码实现非常简单，但它是一道**思维题**。目的在于完全确认你是否真的从底层理解了闭包的运作机制。

🏆 挑战任务

📝 需求描述

我们有一个如下的立即执行的函数表达式（IIFE）。

1. 你的任务是：在这个函数的末尾，附加一个事件监听器，当网页上的 `body` 元素被点击时，将提取到的 `header` H1标签的颜色更改为蓝色(blue)。

2. 重要限制：你绝不能在回调函数中重新使用 `document.querySelector('h1')` 去查找元素！你只允许使用外层现成的 `header` 变量。

3. 真正的考验：完成代码后，用自己的话向自己（或周围的人/小狗/橡皮鸭）解释，为什么这个事件监听器能够奏效。

💡 解析与答案

我们需要给 body 绑定点击事件，并在事件回调里修改变量：

(function() {
  const header = document.querySelector('#myHeader');
  header.style.color = 'red';

  // 答案代码：
  document.querySelector('body').addEventListener('click', function() {
    header.style.color = 'blue';
  });
})();

为什么这段代码能奏效？(原理剖析)

能写出这段代码非常简单，但这道题的精髓在于你能否说出它的前因后果：

  • 这是一个 IIFE 函数。一旦该文件/脚本加载完成，这个匿名函数立即执行，header 变量立马被创建分配。
  • 毁灭降临：执行到最后一行注册完监听器后，这个 IIFE 瞬间消亡了。它的执行堆栈被弹出销毁，包裹它的作用域理应随之彻底消失。
  • 闭包显威：尽管 IIFE 死去了，但注册的回调函数却被挂载到了 DOM 节点上存活了下来。而且在它诞生的瞬间，它背起了沉甸甸的背包（闭包），将 header 这个节点内存指引悄悄塞了进去随身携带。
  • 点击时刻：可能是在 1 秒后，也可能是在 1 小时后。用户点击了页面 body。这个在闭包保护下存活的回调函数被拉回主线程引发执行。虽然此时周遭全是荒凉的全局环境，当它被指派执行 header.style.color = 'blue' 时，它不仅没有报 ReferenceError，反而不慌不忙地打开了身上的背包囊，取出了那个保存完好的 header 引用并修改了它的样式。

恭喜你！如果你能顺口溜出上述的底层理论，这意味着你已经真正驯服了 JavaScript 最深奥的一匹野马：闭包。
