🎯 概述

上节课我们通过在一个函数内部 `return` 另一个函数从而捕捉到了闭包现象。但这其实只是闭包发生的场景之一。这节课我们将看到，只要函数在其出生地外围能被**外部持有**（比如赋值给外部变量，或者交由定时器在未来环境执行），闭包就会悄然降临。

1. 例一：函数的"重生"与记忆更替

假设外层有个空变量。有两个不同的局部作用域，先后把局部生成的函数挂载到这个外部变量上。由于它不断在新的地方被“重新分派和出生”，它的闭包（即它的故乡记忆）也会不断更新。

3. 优先级之战：闭包 VS 作用域链

我们在讲作用域链时说过，如果变量在当前函数找不到，它会随着代码视觉层级去全局里找。

但是如果闭包里（记忆背包里）也存着一份同名变量，全局作用域里也有一份一模一样的同辈名变量，函数应该以谁为准？

> 🥇 **铁律：闭包永远享有最高优先级**
函数总是会优先检查自己的**闭包背包**（它出生的家乡）。只有当它发现背包里也没这个变量时，才会转头去普通的作用域链（比如外层的全局环境）去寻找。 
let perGroup = 1000; // 如果是这 1000 个乱入的全局数据生效，那登机组就炸包了

const boardPassengers = function(num, wait) {
  const perGroup = num / 3;

  setTimeout(function() {
    // 尽管外部还有一个 perGroup 在伺机而动
    // 但这个函数的闭包（它刚出生时看到的同屋变量 perGroup = 60）具有特权优先被采用！
    console.log(perGroup); 
  }, 1000);
};

// 依然会输出 60
boardPassengers(180, 1);

❓ 理解检测

1. 下图 `setTimeout` 定时器函数能够访问到外部函数的 `n` 变量的最主要原因是什么？
`function start(n) { setTimeout(() => console.log(n), 1000); }`
A) 因为 `start` 函数会一直阻塞停顿在那里等待 1 秒，等待着被访问。
B) 因为传递给定时器的那个箭头回调函数在创建之时，顺手牵羊用闭包带走了 `start` 函数的局部变量（即参数 n）。
C) 因为 n 被自动提升成了全局变量。
正确答案: B。这是典型的定时器/事件监听器闭包场景，父级上下文虽消亡，回调带着闭包存活。
2. 关于闭包(Closure)和常规作用域链(Scope Chain)，描述正确的一项是？
A) 函数如果寻找不到一个内部变量，会优先去闭包大礼包里面找，如果闭包也找不到，再去外部作用域链找，闭包优先级更高。
B) 寻找不到变量时，会优先去全局作用域链找，只有实在找不到时才迫不得已去解开闭包寻找。
C) 这两者其实是互斥的，如果有了闭包，就不存在作用域链了。
正确答案: A。闭包比外部的全局作用范围具有更高的搜寻优先级。
