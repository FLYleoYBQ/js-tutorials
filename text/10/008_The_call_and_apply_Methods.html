🎯 概述

当对象内部的方法被单独提取提取出来变成普通函数时，它原有的 this 光环就会惨遭剥夺。如何强制让游离在外的函数识别它真正的“主子”？答案就是利用 JavaScript 所有函数对象都自带的 .call() 和 .apply() 附魔大招！

2. 拯救 this: call() 方法强制指派

我们需要明确、强硬地告诉 JavaScript 引擎：“我要你在这个函数执行的瞬间，把 this 指向我给你的目标对象！”——这就是 call() 第一参数发挥作用的地方。

3. 历史遗留的 apply() 及现代解法

除了 .call()，还有一个孪生兄弟叫做 .apply()。它们的作用一模一样（指定 this），唯一的区别在于它们接收原函数参数的形式：

  • call()：逐个列出传参（像是点名）。
  • apply()：只收一个载满参数的**数组**。
🚨 ES5 时代的 apply (The Apply Way)
const flightData = [583, 'George Cooper'];

// 第一参数是目标对象，第二参数是数组
book.apply(swiss, flightData);
✨ ES6 现代重构写法 (Call + Spread)
const flightData = [583, 'George Cooper'];

// 配合展开语法(...)，彻底抛弃 apply()
book.call(swiss, ...flightData);

在现代 JavaScript 开发中，apply() 已经用得非常少了，大家更倾向于永远使用 call()，并用 ... 展开操作符处理数组数据，读起来更顺畅连贯。

❓ 理解检测

1. 我们为什么能对一个函数写出类似 `.call()` 或 `.apply()` 这样的调用？
A) 因为那是浏览器的 DOM API 特供方法。
B) 因为函数在 JavaScript 中实质上就是 Object（头等函数），而只要是对象就能继承和拥有自己的方法属性。
C) 这是因为编译器的语法糖自动转换的。
正确答案: B。这是呼应上一节课“函数也是一种值/对象”最生动的实例。
2. 阅读以下代码：

const obj = { val: 100 };
function logger(a, b) { console.log(this.val + a + b); }
logger.call(obj, 10, 20);

最终输出结果是多少？
A) 130
B) 30
C) NaN (报错)
正确答案: A。`call` 把函数内的 `this` 指向了 `obj`，所以 `this.val` 解析为 `100`。随后的传参分别是 10 和 20。加在一起为 130。
