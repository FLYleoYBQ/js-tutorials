2. 抽象 (Abstraction) 的力量

在上面的例子中，我们为什么要费这么大劲将逻辑拆开呢？其实这就是编程中最重要的思想之一：抽象（Abstraction）。

抽象意味着我们隐藏了代码的具体实现细节，因为在更高的层级，我们其实不关心这些细节。这样可以让我们在更高的层级去思考问题。

> 🧩 **现实类比**：就像你去餐厅吃饭。你是“高阶函数”，厨师是“回调函数”。你只需要告诉厨师（调用回调）：“我想要牛排（输入）”。至于牛排要怎么解冻、煎多久、放多少胡椒（低层实现细节），你根本不需要管。

在这个代码中：transformer 函数（高级层）根本不在乎字符串到底是变成了一个词，还是首字母大写。它把粗重累赘的底层数据处理工作委托（Delegate）给了 oneWord 和 upperFirstWord 这些底层函数。

❓ 理解检测

1. 当我们写 `document.body.addEventListener('click', highFive())` 时，代码能正常作为回调工作吗？
A) 可以，这就是标准写法。
B) 错误。加了 `()` 就代表立即执行了 `highFive` 并将其返回值传给了监听器，而不是把函数本身当作回调传过去。应该写成 `highFive`。
C) 错误。DOM API 不支持高阶函数。
正确答案: B。这是新手极易犯的错。如果你加上了 `()`，JavaScript 引擎在读取这行代码时就会立刻运行该函数。传入高阶函数时，千万要忍住不打括号，要把函数名字当做一个“包裹”扔过去。
2. 为什么我们如此执着地在 JavaScript 中使用回调抽象？（多视角）
A) 因为没有回调的话，JavaScript 无法操作外部变量。
B) 仅为了炫技。
C) 它不仅让代码拆分开来便于复用，更是分离了逻辑关注点，用高层控制器调用基层干活工人，实现了【抽象】。
正确答案: C。正如 Jonas 强调的，这是最核心的设计模式！你把实现不同目标的具体步骤隔离出来，高层函数只管发号施令。
