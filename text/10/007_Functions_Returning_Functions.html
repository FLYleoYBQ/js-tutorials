🎯 概述

上节课我们探讨了接收函数作为参数的高阶函数。今天我们来玩点“反向操作”：编写一个直接将另一个新函数作为结果返回出来的函数。理解这种连续套娃的执行语法，是进阶函数式编程和攻克“闭包”难关的必经之路。

1. 基础返回模式：两步走

让我们创建一个很简单的场景：我们希望有一个“问候语制造机”函数 greet。你喂给它一个打招呼的方式（比如 'Hey'），它就会“吐给”你一个量身定做的打招呼专门函数。

🤔 等等，内层函数为什么还能记住 greeting 参数？
这其实是因为 JavaScript 中非常硬核的一个机制——闭包（Closure）。内层函数“抱住了”它诞生时的那个外层环境里的变量。这也是为何 greeting 在 greet 执行完后并没有被销毁的原因。不过不用着急，我们会在本章末尾专门通过图解深度剖析闭包。

2. 连续调用大绝招：一步到位！

其实，我们没有必要非得把返回出的函数存进一个中间变量（比如 greeterHey）里。既然 greet('Hello') 的计算结果就是一个实实在在的函数对象，那我们当然可以紧接着加上第二对圆括号把它立即调起来！

3. 重构挑战：纯箭头函数

现代前端开发中大量使用箭头函数来让这种高阶套娃变得极其极简。让我们用纯箭头函数重构上面的传统 function() 写法：

🚨 传统写法 (Traditional Function)
const greet = function(greeting) {
  return function(name) {
    console.log(`${greeting} ${name}`);
  };
};
✨ 箭头极致重构写法 (Arrow Function)
const greetArr = greeting => name => console.log(`${greeting} ${name}`);

// 同样可以紧凑调用：
greetArr('Hi')('Sarah');

这在一开始看起来可能非常诡异：一个箭头接着一个参数接着又一个箭头。但只要你明白最左侧其实就是外层函数，中间是它 return 的内层函数参数，最右边的是内层函数的执行内容，这种形式在像 React 或者函数式编程库中是非常标准的写法。

❓ 理解检测

1. 对于 `const multiplier = factor => num => num * factor;` 这行代码，我要如何正确的传入因数 5 和基数 10，让它返回出 50 呢？
A) `multiplier(5, 10)`
B) `multiplier(5)(10)`
C) `multiplier((5) => 10)`
正确答案: B。这是典型的柯里化（返回新函数）连环调用写法。第一组括号 `(5)` 让第一层函数返回并锁定 `factor`，第二组紧跟的括号 `(10)` 把 10 传给了返回出内层的新函数的 `num` 变量，从而完成计算。
