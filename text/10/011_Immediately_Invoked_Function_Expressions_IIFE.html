立刻执行的函数表达式 (IIFE)

📺 来源：011 Immediately Invoked Function Expressions (IIFE).en.srt 📂 章节：第 10 章
📌 知识脉络
  • 回顾：作用域链 (Scope Chain) 与变量遮蔽，表达式与语句的区别。
  • 目的：学习一种"阅后即焚"的一次性执行技术。

🎯 概述

有时我们需要一个函数仅仅执行一次，并且永远不会被再次调用。比如我们要初始化我们的整个应用程序，或者进行一些初始环境判定。如何做到“代码一加载就立刻执行并且不留痕迹”？这就是 IIFE 被设计出来的主要初衷。

1. 什么是 IIFE？怎么写？

如果你随便写一个普通的匿名函数 function () { console.log('Hi') }，JS 引擎会报错，因为它期待在这个位置出现一个合法的函数声明（带有名字）。

我们的破局思路是：将整个声明包裹在一对圆括号 () 中，欺骗编译器，告诉它这是一个**表达式（Expression）**而不是声明。然后，在这个大括号外面再加一个小括号，立刻调用它！

2. 前 ES6 时代：为什么要发明 IIFE？（数据隐私）

在没有现代 JS 特性（let/const 和块级作用域）的蛮荒时代，控制变量生命周期极其困难。为了保护某些隐私变量（防止在全局被人随便覆盖修改，比如重要的密钥、初始配置值等），唯一的做法就是——创建一个空壳函数引发一个新的作用域隔离网。

> 🛡️ **数据隐私与封装 (Encapsulation)**：
外部的作用域链无法通过时光机获取内部的作用域内存。因此在普通函数的花括号 {} 里定义的任何东西对外界都是不可见的。
将代码放进 IIFE ，意味着这些变量创建在这个一次性牢笼里，永远无法泄漏出来！ 
(function () {
  const isPrivate = 23; 
})();

// 访问隐私数据遭到无情拒绝
console.log(isPrivate); // 🚨 ReferenceError: isPrivate is not defined

3. 现代 JS 中的 IIFE 地位：风光不再？

然而现在是 ES6 当道的时代！要想进行数据隐私封装，完全不需要费老大的劲去造一个空壳函数了。

因为现代 JS 的 let 和 const 支持**块级作用域 (Block Scope)**。这意味着任何一个简单的独立花括号对 { }，本身就能创造一个只对自己可见的安全气泡：

index.js

💡 总结一下：如果是为了保护变量隐私，单独画一个 {} 的块级作用域（并配合 let/const）足矣，IIFE 在这一目的上已被淘汰。
但是，如果是纯粹为了保证代码块只被执行一次（比如以后你会见到的 async/await 顶层调用模式），IIFE 仍然在现代开发中大放异彩。

❓ 理解检测

1. IIFE 最外面包裹的那一层圆括号 `()` 的语法作用是什么？
A) 因为那是用来装传入参数的地方。
B) 它是为了欺骗 JavaScript 解析引擎，将内部的内容强制判定为一个值（表达式），而非一个待声明的语句。
C) 这是 JQuery 框架自创的语法糖，后来被 JavaScript 标准吸收。
正确答案: B。当你以 `function` 单词开头时 JS 是期待语句的。通过外部括号强制执行上下文转换。
2. 在现代 ES6 环境中，如果我们只是想防止临时变量挂载到全局污染环境，最简单/最推荐的做法是？
A) 仍然写一个完整的 IIFE，这是雷打不动的标准。
B) 将所有变量都用 `var` 声明在文件顶部统一管理。
C) 用一对孤立的大括号 `{ }` 创建代码块，在里面使用 `let` 或 `const` 声明变量即可。
正确答案: C。块级作用域的引入已经大大简化了保护变量不外泄所需的样板代码量。
