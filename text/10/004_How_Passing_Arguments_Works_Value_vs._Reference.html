参数是如何传递的：值传递 vs 引用传递

📺 来源：004 How Passing Arguments Works Value vs. Reference.en.srt 📂 章节：第 10 章
📌 知识脉络
  • 前置知识：基础数据类型与引用类型的区别（内存堆与调用栈基础）
  • 后续扩展：深度解析高阶函数、副作用（Side effects）

🎯 概述

当我们将一个变量作为参数传入函数时，究竟发生了什么？这节课我们将深入底层寻找答案。通过对比基本类型（Primitive type）和对象（Reference type）在参数传递时的不同表现，我们将一劳永逸地解决这个引发最多初学者 Bug 的核心概念，并破除一个被误传已久的谣言——“JavaScript 存在按引用传递”。

1. 按值传递机制演示

让我们来模拟一个登机 checkIn 函数，尝试在函数内部修改传进来的数字和对象，看看外界原始变量是否会受影响。

index.js

🔍 执行追踪：
flight 是基本类型（字符串）。将其传递给函数的形参 flightNum 时，仅仅是**复制了它的值**。它们在内存中是相互独立的。所以 `flightNum = 'LH999'` 不会影响外界的 `flight`。

jonas 是对象类型（存储在内存堆中）。当把它传进函数成为 passenger 参数时，复制的不是对象本身，而是那个对象在内存堆里的**指向地址（引用，Reference）**。passenger 和外界的 jonas 指向物理世界里的同一块内存区域。因此修改 passenger.name 也就是修改外面的 jonas.name！

4. 澄清辟谣：JavaScript 只有按值传递！

> 💡 **核心警钟**：即便你看到了参数像对象那样“连体”变更，**JavaScript 中也是不存在绝对的「按引用传递（Pass by reference）」机制的**！

在 C++ 等某些语言中，你可以将 5 的引用地址直接传过去，这就叫“按引用传递”。但 JavaScript 从来不支持把基本类型的引用传过去。

对于对象：实际上 JavaScript 传递的也是一个“值”，而这个**“值”的内容恰恰是一串承载了堆内存地址的引文串（Reference Value）**！
简而言之：我们是在**按值传递引用（Pass a reference by value）**，而不是真正语言学上底层概念的按引用传递。 这是一个非常容易造成混淆、却又极度重要的区分！

❓ 理解检测

1. 当我们将一个对象作为实参，传递进函数的形参中时，我们实际上复制并传递了什么？
A) 整个对象在内存堆里的克隆体
B) 一串指向该对象在内存堆位置的地址引用（被当作一种特殊值拷贝传进去）
C) JavaScript 直接建立了一根底层指针，开启了按引用传递（pass by reference）的通道
正确答案: B。这正是 JavaScript 的精髓。传递的是记录对象位置的“一串门牌号”（也就是引用的值）。我们是在通过按值传递的方式来传递一个引用，因此函数内外拿着一模一样的门牌号，去同一个家里捣毁家具，外面的主人自然会发现家里被砸了。
2. 以下代码执行后，外层 a 和 b.name 会是多少？

let a = 1; let b = { name: "Tom" };
function mutate(x, y) { x = 100; y.name = "Jerry"; }
mutate(a, b);
A) a = 100, b.name = "Jerry"
B) a = 1, b.name = "Tom"
C) a = 1, b.name = "Jerry"
正确答案: C。`a` 是基本类型（数字），拷贝的就是 `1`。函数内 `x=100` 不会波及外层。`b` 是对象引用，`y` 收到了对该对象的访问权，所以修改了公共对象内部属性，导致外界也能察觉。
