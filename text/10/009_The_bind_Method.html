bind() 方法与偏函数 (The bind Method)

📺 来源：009 The bind Method.en.srt 📂 章节：第 10 章
📌 知识脉络
  • 前置关联：call 和 apply
  • 核心差异：call 立刻执行函数；bind 则不执行函数，而是衍生并返回出一个永久绑定了 this 的新函数。

🎯 概述

如果说 call 是给函数穿上了一次性的 this 机甲立即去战斗，那么 bind 就是给函数永久性地植入了 this 核心芯片，并克隆出一个随时可以召唤的独立战士。 bind 方法在现代前端（特别是 React）的 DOM 事件绑定以及函数定制中，占据着绝对统治的地位。

2. 核心大坑与解法：DOM 事件监听器中的 this

这是真实编程中最容易绊倒新手的场景。当你把一个对象的方法直接当做事件监听的回调函数时，方法内部的 this 将会失控，转而指向触发事件的 DOM 元素（比如按钮）本身。

> 🚨 **灾难再现**：
document.querySelector('.buy').addEventListener('click', lufthansa.buyPlane);
在这个回调里，this 就不再是 lufthansa 对象，而是这个 DOM 的 button 元素！此时 this.planes++ 会得到 NaN，因为按钮根本没有这个属性。

怎么破局？用 bind！ 既然 addEventListener 需要我们传入一个函数体（不能直接执行 call），我们就给它抛一个用 bind 提前捆好 this 的新炮弹：

// ✅ 完美解法：传入一个被永久绑定了 lufthansa 对象的新函数
document.querySelector('.buy').addEventListener('click', lufthansa.buyPlane.bind(lufthansa));

3. 核心应用：偏函数/预设参数 (Partial Application)

很多时候我们用 bind 根本不是为了对象上下文（甚至不在乎 this），而纯粹是用它来预设某些参数，从而由一个通用函数衍生出一个更具体的函数。

index.js

这种仅预设一部分参数，让后续调用更简便的技法，在函数式编程中被称为偏应用（Partial Application）。这和默认参数略有不同，因为这不仅是提供了默认值，而是实打实地生成了一个业务上的新特定变体函数。

❓ 理解检测

1. `call` 和 `bind` 最核心的差异是什么？
A) call 可以跨文件使用，而 bind 只能在同一作用域内使用。
B) call 接收对象参数，而 bind 接收数组参数。
C) call 会立刻执行该函数并返回值；bind 不会执行函数，而是返回一个绑定了 this（及可能带有预设参数）的新函数。
正确答案: C。一定要牢记：bind 是制造一个等待后续调用的函数的工厂机器。
2. 阅读以下用于构建 API URL 的通用构建函数，怎么使用 `bind` 派生一个专属的获取 user 接口的变体 `getUserUrl`？
`const buildUrl = (protocol, domain, endpoint) => \`\${protocol}://\${domain}/\${endpoint}\`;`
A) `const getUserUrl = buildUrl.bind(null, 'https', '/users');`
B) `const getUserUrl = buildUrl.bind(null, 'https', 'api.example.com', 'users');`
// 以及也可以：`const buildApi = buildUrl.bind(null, 'https', 'api.example.com');`
C) `const getUserUrl = buildUrl.bind('api.example.com', 'https', 'users');`
正确答案: B。bind 第一参数是被当做 `this` 绑定的，这里我们不用它所以传 `null`；随后从左至右固定所需的参数。
