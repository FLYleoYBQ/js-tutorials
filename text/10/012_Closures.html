📌 知识脉络
  • 基石支持：第八章 执行栈 (Execution Stack) 与变量环境 (Variable Environment)。
  • 场景关联：上节课我们提到函数返回函数时，内层函数能神奇地记住外层函数的变量，这就是依靠闭包。

🎯 概述

闭包被公认为是 JavaScript 中最被人难以理解、误解最深，却又最核心、最常考的机制。如果没有它，JavaScript 中的高阶函数、回调、React Hooks 等架构将全部崩塌。今天我们不看长篇代码，只看核心概念和底层运作原理。

1. 什么是闭包？底层魔法拆解

在早前的课程中我们了解到，一个函数执行完毕并 `return` 之后，它的执行上下文（Execution Context）就会从调用栈里弹出并被销毁。理所应当的，存在于这个环境里的所有变量理论上也该灰飞烟灭了。

但是！由于我们在外层函数里返回了一个内层函数，魔法就此发生：

📚 闭包的终极定义

一个函数总是能访问它被“创建”时的那个执行上下文的变量环境（Variable Environment），即使创建它的那个执行上下文已经消亡了。

也就是说，即便外层函数死去了，“变量环境”并没有随之陪葬。它的幽灵依然存活于 JS 引擎的某个角落。内层函数在诞生之初，就悄悄地将这个“幽灵环境变量”跟自己绑定在了一起。当它发现自己在自己的小层级里找不到需要的变量时，JS 不会立刻报错，而是会顺藤摸瓜去它身上的幽灵环境（也就是闭包）里拿。

2. 两个直观类比打通任督二脉

如果上面的执行栈原理解释听得人头大，Jonas 给你准备了两个绝妙的类比：

🎒

类比一：随身携带的记忆背包 (The Backpack Analogy)

把函数想象成一个人。当他在某个密室（外层函数环境）出生时，他把屋子里所有眼前能看到的变量统统塞进了一个背包里。随后密室坍塌了，他走了出去。但在他漫长的一生中，无论走到哪，那个装着故乡变量的背包永远背在他的身上。这就是闭包。

🏡

类比二：永远不忘故乡的人 (The Hometown Analogy)

闭包就像一个永远不会忘记出生地风月的人。一个人离开了故乡前往大城市打拼（函数被提升或返回到全局被调用），但他依然能随时想起故乡房子的布置（能访问诞生时的那个词法作用域链）。

3. 闭包的三个绝对原则 (你无权干涉的黑暗魔法)

虽然理解了闭包是什么，但是要注意以下三个开发原则：

  1. 它是自动发生的：我们绝不需要手动去 createClosure()。它是语言核心机制，每次函数套函数时它在你根本没察觉时就已经发生了。
  2. 它是隐身的：闭包是一个内部对象。在你的代码中，**没有任何直接的 API** 能够把手伸进背包里提取闭包内的变量。你无法写 console.log(func.closure.count);。你能做的就是通过内部函数运行时的表现间接感受到它的存在。
  3. 你可以通过特殊手段窥探它：我们可以利用浏览器开发者工具（或在 Chrome 使用 console.dir(func)）。如果展开方法自带的 [[Scopes]] 内部属性标签，由于这是 V8 引擎底层暴露的信息，你就能亲眼看到一个名为 Closure (...) 的对象，以及它抓在手里的那些变量值！

❓ 理解检测

1. 为什么我们说闭包是一个 “背包 (Backpack)”？
A) 因为 JavaScript 会把文件里所有的变量都打包压缩，从而提升运行速度。
B) 因为当函数在特定的作用域被创建（出生）时，它会牢牢“抓住”那个作用域里的变量，并且无论这个函数走到哪（在哪被最终调用），它都能从背包里掏出当初抓到的变量来用。
C) 因为闭包就是一个特殊类型的数组，可以用来存放很多临时数据。
正确答案: B。这是理解闭包最形象的思维模型。它携带了它出生时的外围环境变量。
2. 我该如何通过代码显式地（Explicitly）在闭包里获取或者修改某个变量呢？（比如获取上面例子里的 passengerCount 数值进行赋值修改）
A) 可以通过 `booker.closure.passengerCount` 访问。
B) 可以使用 `window.passengerCount = 0;` 来重置覆盖它。
C) 我们根本无法显式地从外部代码直接触碰闭包里的变量。
正确答案: C。闭包是属于 JS 引擎内部属性。它是“数据隐私（Data Privacy）”之所以能实现的关键，因为外部任何代码都绝对摸不到闭包里的值。唯一能修改它的，只有持有该背包的函数自己。

📖 词汇速查表 (Cheat Sheet)

中文术语 英文术语 简明释义
闭包 Closure 使内部函数能够访问外部函数的变量的一个机制。在函数创建的瞬间同时被创建。可以简单理解为函数随身携带的包含创建时环境状态的“背包”。
内部属性 [[Scopes]] 在 JS 规范中用双括号包裹的标记，表示这是引擎内部专用属性，开发人员不能从普通代码调用。浏览器控制台中常借由 console.dir() 暴露供人调试闭包。
