Rolling the Dice (掷骰子业务逻辑)

📺 来源：016 Rolling the Dice.en.srt 📂 章节：第 07 章

上节课我们通过初始化把骰子图片藏起来了，把双方分数清零了。这节课我们将正式赋予 “Roll dice (掷骰子)” 按钮灵魂，让游戏动起来！

1. 绑定事件与生成随机点数

跟之前的基本操作一样，抓取 Roll 按钮并监听点击事件。在内部产生一个 1 -> 6 的随机数字，代表单次掷出的点数：

const btnRoll = document.querySelector('.btn--roll');

btnRoll.addEventListener('click', function() {
    // 1. 生成 1-6 伪随机数
    const dice = Math.trunc(Math.random() * 6) + 1;
    
    // ... 后续逻辑
});

注意，这个 dice 变量必须写在事件监听函数的里面，而不是像之前的预备变量写在外面。因为每次玩家点击，都必须要生成扔出新的数字！

2. 动态操控 <img> 的 src 属性

既然扔出了点数，首先要在刚开局被隐藏的图片再次显示：diceEl.classList.remove('hidden')。
接着，关键的一步来了：前端文件夹里早就放好了六张名叫 dice-1.png 到 dice-6.png 的图片。我们要怎样根据刚刚生成的数字，告诉 <img> 标签应该吃哪张图呢？

答案是：直接通过 JavaScript 操弄 src 属性。就像我们可以用 `.textContent` 改文字、用 `.style` 改样式一样，我们可以用 .src 动态改变图片的来源路径。

btnRoll.addEventListener('click', function() {
    const dice = Math.trunc(Math.random() * 6) + 1;
    
    // 揭开隐藏的图片
    diceEl.classList.remove('hidden');
    
    // 🔪 利用模板字符串，将随机数字插拔式塞进图片名称里
    diceEl.src = `dice-${dice}.png`;
});

通过这个小技巧 `dice-${dice}.png`，如果 dice 变量是 3，浏览器就会立刻去加载 dice-3.png 并覆盖原来的源，骰子界面就瞬间“变化”了！

3. 状态持久化：作用域陷阱

掷出点数后，我们需要记录玩家在本小回合中持续累加的数字 (Current Score)。很多新手会这样写代码：

btnRoll.addEventListener('click', function() {
    // ❌ 错误示范：致命的作用域陷阱！
    let currentScore = 0; 
    currentScore += dice;
    console.log(currentScore);
});

🚨 错误分析：
在这个回调函数里，一切内部变量的生命周期都只有“一次点击的瞬间”。当你每次点击按钮，里面的所有代码重新执行，let currentScore = 0 就会被重新喊一声“集合清零”。这意味着，你的分数永远只能记录单次扔出的点数，无法不断向上叠加！

为了让状态能够 跨越多次点击持久化存在，必须把它提升 (Lift Up) 到函数外部的“全局”空间中去。

// ✅ 正确做法：将状态写在广阔的全局天地里
let currentScore = 0;

btnRoll.addEventListener('click', function() {
    const dice = Math.trunc(Math.random() * 6) + 1;
    // ...
    // 只有在外面建立的银行账户，这里的汇款记录才不会被清空
    currentScore += dice; // 等价于 currentScore = currentScore + dice
});

4. 游戏的核心分支判定

在获得了不断累积的 currentScore 之后，我们迎来了流程图 (Flowchart) 中最关键的分岔引路牌。游戏规则是：只要掷出的不是 1，就一直把分数加到当前累计上；一旦掷出了1，本回合爆掉，累计分作废并且立即切换对手。

btnRoll.addEventListener('click', function() {
    const dice = Math.trunc(Math.random() * 6) + 1;
    diceEl.classList.remove('hidden');
    diceEl.src = `dice-${dice}.png`;

    // 👉 核心业务逻辑
    if (dice !== 1) {
        // 增加累计分
        currentScore += dice;
        // 把数据印刷到网页上对应的字眼里面 (目前暂时硬编码写死在 Player1 身上测试)
        document.getElementById('current--0').textContent = currentScore;
    } else {
        // 掷到了1：切换到下一位玩家！(下节课填坑)
    }
});

我们已经实现了“点骰子 -> 随机数 -> 图片更替 -> 累计分数变动” 的单边通路。在下一节，我们将完成 `else` 爆点环节中极其骚气的设计：如何在代码中平滑地切换真正的两位对局玩家轮换。

🧪 学习验证

1. 变量定义的“位置 (Scope/作用域)”决定了数据的生死。下面两个场景哪一组定义位置是完全精准的？
A) 每次丢出的随机数字 `dice` 必须放在外面全局；当前累加总分 `currentScore` 必须放在点击事件里面。
B) 当前累加总分 `currentScore` 必须放在外面全局，因为它要跨越多次不同的点击累计而不被重置；随机数 `dice` 必须放进点击事件内，因为每一次点击都需要全新的数字。
👍 正确！ 解析：这就是状态管理的基础直觉。持久留存的资产，放金库 (外部全局)；随抛即忘的临时草稿纸，放口袋 (内部局部)。
