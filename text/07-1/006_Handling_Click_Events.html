Handling Click Events (掌控点击事件)

📺 来源：006 Handling Click Events.en.srt 📂 章节：第 07 章

我们的 JavaScript 能够通过 document.querySelector 主动出击去读写网页内容。但现代 Web 应用最吸引人的地方在于：它可以响应用户的动作。

1. 什么是事件监听 (Event Listener)？

当用户在网页上挪动鼠标、敲击键盘、点击按钮时，我们称其发生了 Event（事件）。

我们可以给特定的网页元素挂载一个类似窃听器的东西，叫做 事件监听器 (Event Listener)。只要约定的动作（比如点击）一发生，这个监听器就会立刻拉响警报，并执行我们提前准备好的一段代码。

2. 编写点击事件代码

要把点击事件与按钮绑定起来，我们需要用到 addEventListener 方法。它需要两个核心参数：

  1. 你要监听的动作类型名称：此处为 'click'。
  2. 动作发生时应当执行的代码包裹体：即一个 函数 (Function)。
document.querySelector('.check').addEventListener('click', function() {
  // 这里包裹的代码，只有在按钮被点击的那一瞬间才会被唤醒执行！
  console.log('按钮被点击了！');
});

🚨 高度注意：函数作为参数的值传递
在这个语法中，我们是在把一整个 function() {...} 当作第二参数传递给方法。这是因为：在 JavaScript 中，“函数仅仅是一种特殊的值”。
不要在里面加圆括号调用它！ 即 function() 而非 function()()。加了括号它会当场立即执行，而不加括号它只是安安静静作为“后备警报方案”存放着，只等浏览器（JS 引擎）在点击发生时代为调用。

4. 游戏的第一个逻辑分支

现在我们拿到了数字，游戏终于开始运转了。对于接收输入的应用，防守性编程的第一步永远是：“万一用户什么都不写直接按了回车呢？”

如果用户没填任何数字，Number(document.querySelector('.guess').value) 会得到数字 0。

在基础章节我们学过：0 是 Falsy (假值)。

document.querySelector('.check').addEventListener('click', function() {
  const guess = Number(document.querySelector('.guess').value);

  // 如果 guess 为 0 (假)，!guess 就会因为假假得真变成 (真)
  if (!guess) {
    // 捕获到无效输入，向玩家抛出报错信息
    document.querySelector('.message').textContent = '⛔ 未填写数字！';
  }
});

🧪 学习验证

1. 关于 addEventListener('click', function() { ... }) 的执行机制，哪个描述是精准的？
A) 预留在第二参数的 function 只是注册了一套行动方案，只有当目标元素真正发生点击时，JS 引擎才会从后台把它揪出来执行。
B) 一旦程序读到这行 addEventListener 代码，里面的 function 就会立刻被触发一次。
👍 正确！ 解析：这就是我们所说的“回调函数 (Callback Function)”。我们只是把它交接给浏览器，对它说：“这本册子你收着，什么时候发生点击（Click），你再去照着册子执行。”
2. 为什么从 <input type="number"> 里面抓取出来的 value，还需要用 Number() 转换一遍？
A) 不用转换也可以直接用，因为加上了 type="number" 所以它原生就是数字。
B) 任何由网页用户界面获取的字符串输入 (哪怕只允许填数字)，其数据底层的类型永远是文本 String。
👍 正确！ 解析：DOM API 取出来的输入框 value 其实都是包含文本字符（例如 "23" 而不是纯粹数字 23）。在后续做大小比对 (`guess > secret`) 时，为了杜绝奇葩的隐式转换错误，第一步就必须手动通过 `Number()` 净水器将它转化为真数字。
