Switching the Active Player (轮换当前活动的玩家)

📺 来源：017 Switching the Active Player.en.srt 📂 章节：第 07 章

上节课我们留了一个坑：玩家的分数全都毫无脑子地硬编码直接加给了 Player 1（即 ID 为 current--0 的元素）。
实际上，这个游戏在设计 HTML 结构时，把玩家 1 的标志设为了 0 (player--0)，玩家 2 设为了 1 (player--1)，这绝非偶然，而是为了我们今天写代码进行“极速换人”铺好的阳关大道！

1. 状态：我是谁？动态拼装元素 ID

我们首先需要在游戏开局的大环境中，设立一个新的上帝视角变量：activePlayer。它的值必须只能停留在 0 或者 1。

let currentScore = 0;
let activePlayer = 0; // 0 代表左边的玩家，1 代表右边的玩家

既然我们知道谁是活动玩家，那么在修改它 DOM 上的专属位置分数时，就不需要写死了。我们可以用模板字符串 拼出要选取的 ID 名字！

// 【神仙技巧】如果 activePlayer 为 0，拼出来的就是 'current--0'；
// 如果 activePlayer 为 1，拼出来的就是 'current--1'！
document.getElementById(`current--${activePlayer}`).textContent = currentScore;

通过这个极其优雅的模型映射技巧，这一行代码就能动态地决定是把钱装进左边玩家的口袋，还是右边玩家的口袋。

2. 惩罚机制：一旦投出数字 1，立即清零并滚蛋

进入上节课留下的神秘 else 区域：

if (dice !== 1) {
    // ... 累加并渲染分数的正常流程
} else {
    // 💣 倒霉蛋，你投出了 1！

    // 1️⃣ 还没换人之前，先无情地把他在画面上的“当前分数”抹零
    document.getElementById(`current--${activePlayer}`).textContent = 0;
    
    // 2️⃣ 切除他在代码内存池里的累计池子
    currentScore = 0; 
    
    // 3️⃣ 剥夺权力让给另一个人 (三元运算符再现神威！)
    // 翻译：当前是我 0 吗？是的话就变成 1；如果是 1 的话，就变回 0
    activePlayer = activePlayer === 0 ? 1 : 0; 
}

3. 视觉轮转：强大的 classList.toggle()

逻辑上我们换了人，但屏幕上并没有什么变化。在 CSS 里，高亮的活动玩家身上带有一个名为 .player--active 的类名，它的底色偏白，而未活动的另一边则是暗紫色。

此时，如果你脑子里想的是：
“如果当前是 0，我就 classList.remove 1 身上的类名，classList.add 给 0；反之亦然...”

拜托请停止这段复杂的大段 if/else 头脑风暴！
classList 提供了一个极其聪明的杀手级 API，专门用于这种“此消彼长 / 有则减无则加”的开关场景 —— 它就是 toggle() (切换)！

// 无论切给谁，我们在换人时，只要对两边的容器施加这股魔法：
player0El.classList.toggle('player--active');
player1El.classList.toggle('player--active');

💡 Toggle (拨动开关) 的聪明机制：
当执行 `toggle('XXX')` 时，它会侦查元素身上有没有这个阶级。
如果有？它就帮你执行 `remove()` 把它扒下来。
如果没有？它就帮你执行 `add()` 把它穿上去。

由于两边玩家同一时间必然只有一件衣服。所以一起 toggle 它们，就相当于把衣服脱下来直接砸到了对方面前，完成秒换！干净得出神入化。

🧪 学习验证

1. 我们为什么要把两边玩家的 HTML ID 设计成 `score--0` 和 `score--1` 这种带序号的格式，而不是命名为 `score--p1` 和 `score--p2`？
A) 因为 JavaScript 规定 HTML 元素的 ID 必须包含数字，用来帮助底层优化 DOM 的查询速度。
B) 为了“结构映射逻辑”。通过让 HTML 设计出的数字后缀（0,1）完美契合我们在 JS 代码中声明的 `activePlayer` 状态变量值（0,1），实现一行模板字符串代码就能动态操控两个元素的终极优雅。
👍 正确！ 解析：高级前端开发最精髓的思想：让状态数据(State) 与 结构视图(HTML) 建立内在和谐的映射关系。这样一来，你不再是被动地到处点选元素，而是让代码自己推理该去选谁。
