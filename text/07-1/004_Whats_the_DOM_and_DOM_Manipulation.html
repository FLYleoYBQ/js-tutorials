What's the DOM and DOM Manipulation (何为 DOM 及 DOM 操作)

📺 来源：004 What's the DOM and DOM Manipulation.en.srt 📂 章节：第 07 章

🎯 DOM 究竟是什么？

在上一节中，我们使用了 document.querySelector() 抓取了一个元素。你已经不自觉地参与了 DOM Manipulation (DOM 操控)。但具体什么是 DOM 呢？

DOM 全称是 Document Object Model（文档对象模型）。简单来说，浏览器在加载完 HTML 文档后，会自动在内存中把它转换成一种结构化的表现形式。这使得 JavaScript 能够像访问普通对象一样，去读取、修改 HTML 的文本、属性，甚至是 CSS 样式。

💡 核心概念：DOM 充当了死板的 HTML 页面和充满动态逻辑的 JavaScript 代码之间的连接桥梁 (Connection Point)。

🌳 DOM 树的家族图谱

当 HTML 被载入解析时，它被存储为一个树状结构（Tree Structure）。HTML 中的每一个封闭标签（例如 p, h1）在这个树结构中都成为了一个由对象构成的 节点 (Node)。

家族关系词汇： 在描述这棵树时，程序员经常使用血缘词汇。比如 html 是 head 和 body 的 母元素 (Parent)。而 head 和 body 彼此挨着，是 兄弟姐妹 (Siblings)。在这棵树的顶端，坐落着极其特殊的最高指挥官：document 对象。它是整个 DOM 的大门。

另外，在这个模型中，不仅标签是节点，HTML 源码里的每一个**纯文字、甚至加的注释**，也都会在 DOM 树中拥有自己对应的位置节点（例如文本节点）。因此，DOM 是对整个 HTML 文档的完美数字克隆。

🚨 揭秘：DOM 并不是 JS 的一部分！

这是无数新手甚至进阶开发者都会跌入的惊天大误区。

⚠️ 避坑警告：
几乎所有人都会认为像 document.querySelector() 等 DOM 处理方法是 JavaScript 语言自带的功能。大错特错！

事实上，JavaScript 官方核心标准（ECMAScript）里根本没有涉及跟浏览器界面操作相关的任何词汇！那么这些控制页面的魔法到底来自哪里呢？

答案是：Web APIs (Web 应用编程接口)。

  • Web API 就好比是浏览器（如 Chrome 或 Firefox）在背后预先写好的一套庞大且复杂的功能插件库。
  • 它们是用 C++ 或是以其他底层语言实现的，并统一规定了标准的调用方法，**免费提供给 JavaScript 使用**。
  • 这些 API 当然不仅包含 DOM，还包含了定时器、读取地理位置、发出网络请求 (Fetch API) 等等。

由于存在一套统一的《WEB 标准规范》，所有现代浏览器（无论 Chrome 还是 Safari）都遵守了同一套 DOM 规范，这也就是为什么我们的 querySelector 能够在所有平台里运行如飞的原因。

🧪 学习验证

1. 你在代码里写了 document.querySelector('h1')，请问这里的 document 是什么？
A) 它是 JavaScript 语言中定义的最基础数据类型。
B) 它是进入 DOM 树结构的特殊入口点对象，位于 DOM 树的最顶端。
C) 它代表用户的整个操作系统。
👍 正确！ 解析：`document` 是包含在浏览器 Web APIs 中提供给我们的一个对象，用来连接和开启所有对 HTML 界面的操控。
2. 以下关于 JavaScript 与 DOM 的说法，哪个是正确的？
A) DOM 操控的方法（如查询元素），并不属于 JS 核心语言标准（ECMAScript）的一部分，而是属于浏览器提供的 Web API。
B) 安装了 JavaScript 的环境（比如后端的 Node.js），就一定默认带了 document 操作页面的能力。
👍 正确！ 解析：JS 核心只是一门能做逻辑和计算的编程语言。你在写后端系统（比如使用 Node.js）的时候，那里也会运行 JS，可是却没有浏览器界面，当然也就绝对不存在 `document` 和 DOM！DOM 是由浏览器额外赠送的库！
