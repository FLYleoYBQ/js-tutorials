Refactoring Our Code: The DRY Principle (代码重构与 DRY 原则)

📺 来源：011 Refactoring Our Code: The DRY Principle.en.srt 📂 章节：第 07 章

我们的猜数字游戏不仅实现了完整的功能，而且也运行得非常好。但在专业开发中，能跑只是底线。一旦程序跑通，高级工程师的第一反应往往是：“这里有哪些代码是可以精简的？” 这就是 重构 (Refactoring) 的过程。

1. DRY 原则 (Don't Repeat Yourself)

在编码世界有一条著名的铁律：DRY (不要重复你自己)。通读我们写好的长长一串事件监听代码，你会发现同样的一句 document.querySelector('.message').textContent = ... 足足出现了五六次！甚至“猜大”和“猜小”的两个代码块里，几乎 90% 的代码都是原封不动抄过来的。

重复的代码会带来巨大的技术债务：不仅文件臃肿难看，而且某天如果这个类的名字从 .message 改成了 .alert-message，你需要苦逼地在代码里找五六个地方逐一修改，极易遗漏引发 Bug。

2. 合并重复的逻辑分支：巧用三元运算符

让我们先来消灭“猜偏了”的代码冗余。之前我们在判断猜大还是猜小的时候，用了两个独立的 else if (guess > secretNumber) 和 else if (guess < secretNumber)。实际上，这两种情况都属于 猜错 (guess !== secretNumber)，只是最后弹出的提示词不同罢了。

我们可以使用神奇的 三元运算符 将它们合二为一：

❌ 重构前：大篇幅重复
else if (guess > secretNumber) {
  if (score > 1) {
    document.querySelector('.message').textContent = '📈 Too high!';
    score--;
    document.querySelector('.score').textContent = score;
  } else { ... lost game }
} 
else if (guess < secretNumber) {
  if (score > 1) {
    document.querySelector('.message').textContent = '📉 Too low!';
    score--;
    document.querySelector('.score').textContent = score;
  } else { ... lost game }
}
✅ 重构后：干净且干练
// 只要没猜中 (包含了太大和太小)
else if (guess !== secretNumber) {
  if (score > 1) {
    
    // 🔥 利用三元运算符按需生成字符串！
    document.querySelector('.message').textContent = 
      guess > secretNumber ? '📈 Too high!' : '📉 Too low!';
      
    score--;
    document.querySelector('.score').textContent = score;
  } else { ... lost game }
}

3. 提炼公用函数 (Extracting Functions)

接下来对付那堆 document.querySelector 的狗皮膏药。对付散落各地的相同操作，最好的办法是把它塞进一个 公用函数 中。

我们在代码的最上方，声明一个名为 displayMessage 的箭头函数（或者普通函数），让它接收一个 message 文本作为参数，并将赋值 DOM 的脏活累活包裹在里面：

const displayMessage = function (message) {
  document.querySelector('.message').textContent = message;
};

一旦有了这个函数，我们代码中几十处反人类的长句子，就可以瞬间替换为优雅、带有强烈语义的代码：

// 重构前：满眼都是 document 和底层细节
document.querySelector('.message').textContent = '🎉 Correct Number!';

// 💎 重构后：宛如英语般自然易读
displayMessage('🎉 Correct Number!');

通过提炼公用函数修改 DOM，我们的代码不仅变短了，更重要的是它 极其易于阅读和维护（Readable & Maintainable）。当你或者别人一年后再来看代码时，由于函数名清晰地在“自述”，根本不用费劲去揣测 querySelector 到底是在干嘛。

🧪 学习验证

1. 为什么 displayMessage(guess > secretNumber ? '太大' : '太小') 这种写法能够生效？关于三元运算符的核心本质，哪项描述是最精准的？
A) 仅仅是因为 JavaScript 的语法糖支持在函数调用里内嵌 if 语句。
B) 因为三元运算符是一个表达式 (Expression) 产生一个最终的“值 (Value)”。JS 会先把问号表达式结算为一个纯字符串 ('太大'或'太小')，然后再把这个纯净的值丢给 displayMessage 去执行。
👍 正确！ 解析：这就是我们早些时候在基础章节强调过的 "语句 (Statement)" 和 "表达式 (Expression)" 的巨大差异。`if/else` 是语句，不返回值，所以不能当参数塞进括号里。而三元运算符是产生值的表达式，这就让它拥有了极其灵活的“随地结算”能力。
