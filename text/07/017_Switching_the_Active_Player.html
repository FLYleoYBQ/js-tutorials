Switching the Active Player

📺 来源：017 Switching the Active Player.en.srt 📂 章节：第 07 章

🎯 概述

上节课我们把增加的分数死死地挂在了 Player 1 身上。这节课我们来修复这个问题，实现两人游戏的精髓：回合切换。

当某位玩家不幸掷出 1 点时，他当前回合的累积积分会归零，并强制切换到下一位玩家。这中间涉及到数据状态的管理，以及 UI 视觉层面的平滑过渡。

1. 状态：谁在掷骰子？

要让程序知道现在该给谁加分，我们需要在全局环境（外部）新建一个 状态变量 (State Variable)。这就是为什么我们在写 HTML 的时候，把玩家分为 Player 0 和 Player 1，而不是 1 和 2。


// 全局状态变量：0 代表 Player 1, 1 代表 Player 2
let activePlayer = 0; 

// ... 然后在丢出 1 的时候（之前写的 else 块里）切换玩家
if (dice !== 1) {
    // 加分逻辑...
} else {
    // 掷出了 1 的惩罚逻辑：
    // 1. 把当前玩家 UI 上的临时分数清零
    document.getElementById(`current--${activePlayer}`).textContent = 0;
    
    // 2. 状态里的当前分数也归零
    currentScore = 0; 
    
    // 3. ⭐️ 核心玩家切换，利用三元运算符：如果等于 0 那么就变 1，否则变 0
    activePlayer = activePlayer === 0 ? 1 : 0;
}

2. 高级技巧：动态拼接 ID

注意到我们在上一段代码里使用的高级技巧了吗？

以前我们要修改一个文本，必须明确指明元素的名字：getElementById('current--0')。
但在不知道当前到底是谁的回合时，我们可以借助 模板字符串 将 activePlayer 状态变出作为 ID 的一部分组合起来！


// 魔法拼接！如果 activePlayer 是 0，它就会选中 'current--0'；
// 如果换人了，activePlayer 变成了 1，它就会选中 'current--1'
// 我们从此再也不用写两套 if-else 去硬编码查找 DOM 元素了！
document.getElementById(`current--${activePlayer}`).textContent = currentScore;

💡 设计之美： 当你的内部状态数据结构（0 和 1）能与外部 UI 的类名或 ID 号（如 player--0, player--1）完全匹配时，DOM 的操纵就会变成世界上最简单的事。

3. 视觉切换神器：classList.toggle()

数据层面的换人已经完成了，但 UI 界面上代表活跃玩家的那个“半边白亮背景”并没有切过去。在 HTML 中，这个高亮样式是由 player--active 类控制的（默认挂在玩家 0 身上）。

我们当然可以用 contains 检查类名，有就 remove，没有就 add。但这太麻烦了！在这种“非黑即白、非开即关”的场景里，JavaScript 提供了一个终极封装：toggle (切换按钮)。


// 这是上方的 else 块内部增加的视觉切换代码
const player0El = document.querySelector('.player--0');
const player1El = document.querySelector('.player--1');

// toggle 的魔力：如果你有这个类，就移除它；如果没有，就加上它！
player0El.classList.toggle('player--active');
player1El.classList.toggle('player--active');

因为 player--active 这个高亮类最开始只存在于玩家 0 身上，所以无论这两个 toggle 怎么“翻转抽脸”，总是保证有且仅有一个玩家亮起白底！

🧪 学习验证

1. 我们在切换玩家时使用的 `classList.toggle('my-class')` 的工作原理是什么？
A) 它自动检查元素是否包含该类：如果不包含就添加该类，如果包含则移除该类。
B) 强制将指定的类添加到元素上，如果已经有了就不做任何事（等同于 add）。
C) 用新提供的类替换掉该元素当前所有的其它类。
正确答案：A。Toggle 就像真实的房间电灯开关，只需按就完事了，它会自动根据现在的状态（亮或暗）执行相反的动作。
