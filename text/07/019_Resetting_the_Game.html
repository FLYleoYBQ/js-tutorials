Resetting the Game

📺 来源：019 Resetting the Game.en.srt 📂 章节：第 07 章

🎯 概述

恭喜你来到 Pig Game 项目的最后一块拼图！目前我们的游戏已经可以完美运行并决出胜负，但是如果想玩下一局，只能手动刷新整个网页。这就很不“单页应用 (SPA)”了。

点击 "New Game" 按钮重置游戏听起来很简单（把所有分数设为 0，把胜利的黑底色去掉等），但仔细一想：这不跟我们第一次打开游戏时的“初始化状态”一模一样吗？ 为了遵守 DRY (Don't Repeat Yourself) 原则，我们要做一次大型重构。

1. DRY 的终极形态：init 函数

既然“页面初次加载”和“点击 New Game 按钮”都需要执行完全相同的“让一切归零”的操作，我们干脆把这堆散落的代码打包进一个叫做 init (initialization 缩写) 的函数中。


// 把所有的“重置”逻辑都丢进 init 里
const init = function () {
    // UI 清零
    score0El.textContent = 0;
    score1El.textContent = 0;
    current0El.textContent = 0;
    current1El.textContent = 0;
    diceEl.classList.add('hidden');
    
    // UI 样式复原
    player0El.classList.remove('player--winner');
    player1El.classList.remove('player--winner');
    player0El.classList.add('player--active');
    player1El.classList.remove('player--active');
};

💡 幂等操作的容错性： 像 remove('player--winner') 这种代码，哪怕当时元素身上根本没有这个类，JavaScript 也不会报错，它只会默默什么都不做。这就允许我们可以放心地在 init() 里面对两个玩家进行统一的清理扫荡，而不用写一大堆 if 去判断到底是谁赢了该清谁的类。

2. 作用域陷阱 (Scoping) 预警

在把代码搬进 init() 函数时，大家一定会犯一个极其经典的错误：把变量的声明 let... 也顺手剪切进了 init() 里面。


const init = function () {
    // ❌ 灾难操作：在函数内部声明 let
    let scores = [0, 0];
    let currentScore = 0;
    let activePlayer = 0;
    let playing = true;
};
// ... 在下方的卷起骰子事件里 ...
btnRoll.addEventListener('click', function() {
    if (playing) { // ❌ 报错！Uncaught ReferenceError: playing is not defined
        // ...
    }
});

为什么会报错？因为在 JavaScript 中，定义在函数内部的变量只属于这个函数内部，这叫做函数作用域 (Function Scoping)。外面的 btnRoll 试图访问 playing，但 playing 已经被困在了 init() 的高墙之内，外面根本看不见它！

3. 声明、赋值与生命周期

解决这个死锁的唯一标准答案是：在外部（全局）只声明空变量，而在 init() 函数内部只负责重新赋值。


// 1. 在最高层级、外部声明空变量，让它们在全局可见 🌍
let scores, currentScore, activePlayer, playing;

const init = function () {
    // 2. 在初始化函数中，剥离掉 `let`，只做单纯的赋值操作
    // 这样它们就会把值存入到外面那四个全局变量里
    scores = [0, 0];
    currentScore = 0;
    activePlayer = 0;
    playing = true;
    
    // UI 清零等代码...
};

// 3. 页面首次加载时，立即手动召唤 init() 跑一次以分配初始值
init();

// 4. 当按 "New Game" 时，把 init【函数本身】塞给事件监听器
btnNew.addEventListener('click', init);

通过这套设计，无论是刚开局还是重开局，变量的作用域都被完美打通了。这也顺便为你拉开了下一章高级理论课——深入解析 JavaScript 的工作原理 的序幕！

🧪 学习验证

1. 为什么我们不能直接把 `let playing = true;` 写进 `init()` 函数内部？
A) 因为 let 关键字只能在程序的第 1 0 行之前使用。
B) 因为这会把 playing 变成 init() 的局部变量。别的函数（如掷骰子的函数）想要读取/修改它时，JavaScript 引擎会报变量未定义的错误。
正确答案：B。“声明”和“赋值”是两码事。想让各大兄弟函数共享财富，存折（声明）必须开在最大的院子里，而大家都只拿密码去往里存取款（赋值）。

📖 词汇速查表 (Cheat Sheet)

中文术语 代码 / 英文术语 简明释义
初始化函数 init() 编程领域的惯例命名，将使程序回到“原厂设定”或开局状态的一系列动作打包成一个可复用的函数。
作用域 Scoping 决定变量可见性和生命周期的“势力范围”。函数拥有自己的大门，内部创建的变量走不出大门。
