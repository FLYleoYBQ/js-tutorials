Refactoring Our Code: The DRY Principle

📺 来源：011 Refactoring Our Code The DRY Principle.en.srt 📂 章节：第 07 章

🎯 概述

游戏功能终于完善了！但优秀的程序员绝不仅仅满足于“代码能跑”。在之前的章节中，为了快速实现功能，我们写了大量重复的冗余代码 (Duplicate Code)。这违反了软件工程中著名的 DRY (Don't Repeat Yourself) 原则。在本节我们将运用两种利器：三元运算符和自定义函数，让代码脱胎换骨。

1. 重构逻辑：合并“猜错”分支

回看我们之前的 if / else if 语句，“猜大了 (guess > secretNumber)”和“猜小了 (guess < secretNumber)”除了提示文字不同（'📉 Too low!' vs '📈 Too high!'），扣分和 DOM 操作的代码简直一模一样。

我们可以把它们合并成一个 else if (guess !== secretNumber) 模块，然后在内部用三元运算符来决定究竟输出哪段提示文字。

❌ 重构前 (潮湿的代码)

// 猜大
} else if (guess > secretNumber) {
    if (score > 1) {
        document.querySelector('.message').textContent = '📈 Too high!';
        score--;
        document.querySelector('.score').textContent = score;
    } else {
        document.querySelector('.message').textContent = '💥 You lost the game!';
        document.querySelector('.score').textContent = 0;
    }
// 猜小
} else if (guess < secretNumber) {
    if (score > 1) {
        document.querySelector('.message').textContent = '📉 Too low!';
        score--;
        document.querySelector('.score').textContent = score;
    } else {
        document.querySelector('.message').textContent = '💥 You lost the game!';
        document.querySelector('.score').textContent = 0;
    }
}
✅ 重构后 (DRY 代码)

// 只要猜错 (无论是大还是小)
} else if (guess !== secretNumber) {
    if (score > 1) {
        // 利用三元运算符动态生成字符串
        document.querySelector('.message').textContent = 
            guess > secretNumber ? '📈 Too high!' : '📉 Too low!';
            
        score--;
        document.querySelector('.score').textContent = score;
    } else {
        document.querySelector('.message').textContent = '💥 You lost the game!';
        document.querySelector('.score').textContent = 0;
    }
}

2. 重构函数：消除 DOM 操作的重复

除了逻辑块的重复，你有没有发现 document.querySelector('.message').textContent = ... 这句长长的 DOM 操作代码在整个文件中出现了至少 5 次？

如果我们以后想换个 CSS class 名，或者改用其他的方式来提示玩家，岂不是要修改 5 处地方？这就是重复代码带来的维护噩梦。解决办法是：将通用的逻辑提取为一个可以接收参数的独立函数。


// 1. 在全局声明一个用于专门显示消息的函数
const displayMessage = function(message) {
    document.querySelector('.message').textContent = message;
};

// 2. 然后，去代码里到处替换它！
// 修改前：
// document.querySelector('.message').textContent = '🎉 Correct Number!';

// 修改后：
displayMessage('🎉 Correct Number!');

💡 语义化代码 (Semantic Code)： 封装成 displayMessage(msg) 后，代码从“机械指令”变成了“人类可读的语言”。一两年后你再回看代码，不需要去猜 querySelector 是在修改哪个元素的心智负担，光看函数名你就懂它的目的。

🧪 学习验证

1. 关于 DRY 原则（Don't Repeat Yourself），以下哪种说法最准确？
A) 它是为了降低代码的维护成本。如果有一段逻辑重复出现了好几次，当我们需要修改这段逻辑时，只需修改提取出来的函数，而不必到处去改散落的代码。
B) DRY 的核心目的是让代码的运行速度变快，减少 CPU 处理时间。
正确答案：A。DRY 主要的红利在于“可维护性”和“防写错bug”，它对代码性能（执行速度）的提升微乎其微甚至没有影响，但对开发人员的颈椎和头发有巨大的保护作用。

📖 词汇速查表 (Cheat Sheet)

术语 说明
DRY 原则 "Don't Repeat Yourself" (不要重复你自己)，软件工程基本真理，主张单一真实数据源和消除重复。
代码重构 (Refactoring) 在不改变软件外部可见行为的前提下，为了提高代码的可读性和可维护性而对内部结构进行的修改。
三元运算符 ? : 条件 ? 成立时的值 : 不成立时的值；因为它是表达式能返回值，常用于行内直接按条件赋值。
