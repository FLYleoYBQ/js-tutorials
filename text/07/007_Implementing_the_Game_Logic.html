Implementing the Game Logic

📺 来源：007 Implementing the Game Logic.en.srt 📂 章节：第 07 章

🎯 概述

上节课我们成功拦截了用户的点击事件并拿到了输入的数字。现在我们要构建 "Guess My Number" 的核心大脑：比较数字、更新生命值（Score），并且判断游戏是赢了还是输了。

1. 至关重要：应用状态 (Application State)

在游戏中，我们需要记录玩家的当前生命值（初始为 20）。每猜错一次，数字就要减 1。

很多新手会这么做：先用 document.querySelector 把页面上的 20 读出来，减去 1，然后再写回页面。这是一种非常初级且危险的做法！

🚨 千万不要只把数据存在 DOM（网页界面）里！ 因为一旦页面显示异常，或者你想在代码别的地方使用这个数字，你将无从下手。DOM 只是用来“显示”界面的，它不该用来“存储”数据。

正确的做法是：在代码中声明专门的变量来存储这些核心数据，这被称为应用状态 (Application State)。


// 定义在最外层的状态变量
const secretNumber = Math.trunc(Math.random() * 20) + 1;
let score = 20; // 必须用 let，因为分数会递减

document.querySelector('.check').addEventListener('click', function() {
    // ... 后续逻辑中，我们只修改 score 变量，然后再把变量的值映射到 DOM 上
});

2. 核心逻辑：If-Else 嵌套与分数判断

现在我们把所有的逻辑分支全铺开。游戏共有 4 种主分支情况：没写数字、猜中了、猜大了、猜小了。

特别注意，在“猜大了”和“猜小了”的情况下，我们要执行扣分操作。但程序是个瞎子，如果我们不告诉它什么时候停止，即便分数被扣到了 -5，它依然会说“猜大了”。所以我们必须在扣分前额外增加一层守卫条件，判断分数是否还大于 1。


const guess = Number(document.querySelector('.guess').value);

// 场景 1：没有输入
if (!guess) {
    document.querySelector('.message').textContent = '⛔ No number!';
    
// 场景 2：玩家获胜
} else if (guess === secretNumber) {
    document.querySelector('.message').textContent = '🎉 Correct Number!';
    
// 场景 3：猜得太大
} else if (guess > secretNumber) {
    if (score > 1) { // 守卫：只要命还没掉完
        document.querySelector('.message').textContent = '📈 Too high!';
        score--; // 状态变量减 1
        document.querySelector('.score').textContent = score; // 更新 DOM
    } else {
        // 命掉完了，游戏结束
        document.querySelector('.message').textContent = '💥 You lost the game!';
        document.querySelector('.score').textContent = 0;
    }
    
// 场景 4：猜得太小 (由于逻辑雷同，日后我们将学习 DRY 原则重构它)
} else if (guess < secretNumber) {
    if (score > 1) {
        document.querySelector('.message').textContent = '📉 Too low!';
        score--;
        document.querySelector('.score').textContent = score;
    } else {
        document.querySelector('.message').textContent = '💥 You lost the game!';
        document.querySelector('.score').textContent = 0;
    }
}

🧪 学习验证

1. 什么是 "Application State" (应用状态)？
A) 它是浏览器提供的一个内置检查网页是否存活的 Web API。
B) 指的是我们在 JavaScript 代码中专门用于保存应用程序一切相关核心数据（比如当前得分、是否登录等）的变量集合。
正确答案：B。应用状态是现代前端开发最核心的概念之一（特别是进入 React/Vue 等框架后）。数据永远应该保存在代码（内存）中，而 DOM 只是这些状态在用户屏幕上的一层倒影。

2. 在上述代码的守卫条件中，为什么我们写的是 `if (score > 1)` 而不是 `if (score > 0)`？
A) 因为这发生在玩家点击按钮“消耗”生命值之前。如果当前分数是 1，玩家一旦点错，分数就会变成 0，此时应该宣布游戏结束，而不是还能继续减。
B) 因为 JavaScript 在处理 0 的时候会自动将其忽略。
正确答案：A。这是非常典型的编程边界情况考察。由于我们的逻辑是先判断、再减分、再显示。如果不拦截 `>1` 的情况，当得分为 1 时玩家猜错，程序会说“太高了”，并把分数降为 0。但此时游戏其实已经输了，所以必须在最后一步操作发生前卡死！

中文术语 英文术语 简明释义
