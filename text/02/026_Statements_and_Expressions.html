声明陈述 vs 表达式 (Statements vs Expressions)

📺 来源：026 Statements and Expressions.en.srt 📂 章节：第 02 章

在向 JavaScript 高阶语法冲刺前，我们需要花几分钟理清一个所有新手都必须经历的理论门槛。到底什么是“陈述句”，什么情况被称为“表达式”？

1. 本质区别：产出结果 vs 执行动作

概念 人类语言隐喻 核心特征 经典例子
表达式 (Expression) 像构成句子的名次/单词 它一定会产生、或化简为一个具体的“值 (Value)” 3 + 4
1991
true && false && !false
它们最终都会提炼变成一个数字或布尔值
陈述/声明 (Statement) 像一个完整的祈使句 是一个被执行的大块运作动作，通常带着分号收尾。它下达了操作指令，但它自己并不变成一个值。 if (23>10) { let a = "big"; }
switch 语句。
它运作了内部变量，但 if 这个语法块本身无法变成数据给别人用。

2. 模板字面量里的禁忌坑点

理清上面的概念不是为了考试背书，而是因为在后面学习中：JavaScript 引擎在很多地方极其挑食，它明确规定哪些孔洞只能塞“表达式”，哪些只能塞“声明”！

例如，最著名的字面量嵌入：${ } 。它只能接受能够产出确切大小数值的表达式！如果你在里面塞了一个巨大的陈述句动作系统，它直接喷红报错：

// 🟢 完美：这是一个表达式，最终会化简为 46 这个数字
console.log(`我朋友今年 ${ 2037 - 1991 } 岁了。`);

// 🔴 灾难：你把一个庞大的条件判决动作机制塞进了一个需要单词的坑位！
console.log(`我朋友今年 ${ if (23>10) { const str = '大'; } } 岁了。`);
// 浏览器会直接当场掀桌：Unexpected token 'if'
