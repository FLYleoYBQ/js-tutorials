比较两个值是否一样，听起来似乎是编程里最简单的事情。但在 JavaScript 里，官方留下了两个历史版本，它们脾气迥异。

1. 严谨者 === vs 放纵者 ==

符号 名称 工作机制与特征
=== Strict Equality (严格相等) 完全不讲情面！ 只有当两边的值完全一样，且数据类型也完全一样时，才会判决归 true。如果遇到字符串 "18" 和数字 18，直接无情拒绝。
== Loose Equality (宽松相等) 喜欢当和事佬！ 如果发现其中一个不是同类，它会触发暗箱操作（Type Coercion），强行把两边掰成同个类型后再去验证，"18" = 18 会通过。

🏆 终极行业法则

💡 忘了 == 吧，永远且只使用 ===

作为 JavaScript 工程师中一项不成文的共识铁律：为了保持代码的高可预测性和防止低级离奇 Bug 的缠身，编写代码时永远默认使用 `===` 这个严格版本。从大脑中彻底格式化掉那个两个等号的版本，假装它不存在！ 如果真的需要验证字符串和数字是否等同，请手动用 `Number()` 将它们显性对齐！

3. 差异的反面：不等于 !==

与 === 的亲兄弟，是不等于操作符。我们同样有宽松版本 != 和严格版本 !==。老规矩，发誓效忠且永远只使用严格版本：!==

if (favorite !== 23) {
    console.log("Why not 23?!"); 
}
