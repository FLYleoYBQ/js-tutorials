值与变量 (Values and Variables)

📺 来源：005 Values and Variables.en.srt 📂 章节：第 02 章

🎯 概述

编程本质上就是在和数据打交道。而值 (Value) 就是我们拥有的最基础的一段数据。在这个章节里，我们将拆解计算机到底是如何识别一块数据，又是如何将其存入一个叫做变量 (Variable) 的容器中反复调用的。

1. 值与变量的本质

🧩 生活类比：包裹与标签箱子

值 (Value)： 它是具体存在的东西，比如一个玩具熊。在代码中，这可以对应数字 23 或字符串 "Jonas"。
变量 (Variable)： 为了方便管理上百个玩具，你准备了很多箱子。你在一个箱子上贴了标签 first_name，然后把 "Jonas" 放进去。这个加了标签的箱子，就是变量！

2. DRY 重构：为什么需要变量？

假设我们的代码中要使用数十次 "Jonas" 这个名字。如果你把 "Jonas" 写死了 10 次，当你想改成 "Matilda" 的时候，你就要修改 10 处地方。这就是没有变量的灾难。我们来看对比：

🚨 初版冗余写法 (The Naive Way)
console.log("Jonas");
console.log("Jonas");
console.log("Jonas");

// 万一想给用户改名为 Matilda，你要手动找并修改三遍。
✨ DRY 重构变量法 (The Refactored Way)
let firstName = "Jonas"; // ← 这里是真理之源

console.log(firstName);
console.log(firstName);
console.log(firstName);

// 以后需要改名时？只改源头一次：let firstName = "Matilda";
// 后续都会自动变更！这就是 编程不可或缺的力量。

3. 变量的铁血命名法则

在 JavaScript 中给变量起名有很多行规和强硬的法律，你绝对不能瞎起。

📜 行业公认铁规 (驼峰式命名 camelCase)：
如果变量由多个词组成，第一个词全小写，从第二个词开始首字母大写。比如 firstNamePerson。它比 first_name_person (蛇形) 更符合 JS 生态的调性。

🚨 破坏必报错的致命硬着陆：

  • ❌ 不能用数字开头： let 3years = 3; (直接崩溃报错，Syntax Error!)
  • ❌ 除了特殊符号，只能是数字、字母、底线 _、美元符 $： let jonas&matilda = 'JM'; (报错，不允许 &！)
  • ❌ 不能用保留关键字抢名字： let new = 27; 或 let function = 27; (JS 的系统核心词，你不配拿来当变量做箱子！)

🐛 报错实验室：如果不听从规劝使用了 let 3years = 3;，在开发者工具的控制台中，红色的字体会无情地嘲笑你：

Uncaught SyntaxError: Invalid or unexpected token

记住去查报错信息，并且根据右侧的行号（Line number）准确定位！

🌟 高级命名潜规则：

  • ❌ 禁止大写字母开头： 比如 Person。这虽然不报错，但在后期面向对象开发 (OOP) 时，那是**“类(class)”**独占的尊贵特权，咱们做小弟的别瞎冒充。
  • ✅ 绝对不变量 (Constants) 使用全拼大写： 如果有个值打死都不改变，世界毁灭都不变（比如圆周率），则要用全大写：let PI = 3.1415;。
  • 💡 名称要一目了然 (Self-Descriptive)： let myFirstJob = "Programmer"; 永远远比 let job1 = "Programmer" 要漂亮！代码是写给人看的！

🧪 学习验证

❓ 理解检测

1. 下面哪个变量名是完完全全在 JavaScript 中合法的？
A) `let 1stPlace = "John";`
B) `let my-name = "Jonas";`
C) `let $person_Age = 25;`
D) `let function = "Run";`
👍 正确！ 解析：
A 错误因为用数字开头。
B 错误因为使用了横线连字符（这在JS里代表减号，非法）。
C 正确，允许包含 $ 和 _ ，并不受首字母小写的强迫（那是规范不报错）。
D 错误因为使用了保留字。
